# AGENTS.md — соглашения проекта hh-agent

Агент автоматических откликов на hh.ru: Playwright (браузер, без API hh.ru) + LLM-провайдер (Decision решает, Generation
пишет письмо). Работает по требованию: запуск → цикл → выход.

## Базовые принципы

1. **Конфиг — единственный источник параметров.** Поведение — в `config.yaml`, личные данные — в `config.local.yaml`,
   секреты — в `.env`. В коде только дефолты схемы. Одно и то же значение в двух местах — ошибка.
2. **Промпт компактный.** `SYSTEM_PROMPT.md` ≤ 3500 символов (проверяется тестом).
3. **Правда важнее стиля.** В письме только факты из профиля: лучше «опыта нет», чем выдумка.
4. **Данные пользователя локальны.** `data/`, `logs/`, `.env`, `config.local.yaml` не в git.
5. **Чувствительные и секретные данные не логируются и не хранятся в в git**: текст письма, профиль, контакты, токены,
   cookies и другая информация которая является персональными данными согласно Федерального закона № 152-ФЗ «О
   персональных данных».
6. **Один вызов — одна задача.** LLM Decision даёт вероятности, LLM Generation — сопроводительное письмо.
   При расхождении вердиктов побеждает Decision.
7. **Если документация репозитория противоречит существующему коду** - следуй соглашениям, принятым в самом коде, а в
   финальном ответе укажи каждое найденное несоответствие между документацией и кодом.
8. **Ничего сверх задания без согласования.** Не делать того, что не указано прямо в задании;
   любое расширение объёма работ — только после явного согласия пользователя.
9. **В конце задания — замеченное и план доработки.** Всегда выводить, что замечено и что нужно
   доработать, с обоснованием причин.
10. **Длина строки — не больше 120 символов.** Для всех `*.md` документов проекта.

## Поведение, которое держит код

- Отклик отправляется при `P("подходит") > llm.decision.threshold`; критерии — только в конфиге.
- Generation возвращает строгий JSON `{verdict, reason, cover_letter}`, ровно один повтор
  при невалидном JSON.
- Приветствие («Здравствуйте!») и подпись с контактами (`llm.cover_letter.signature`)
  гарантируются кодом; подпись входит в `llm.cover_letter.max_length`.
- Если вакансия требует начать письмо с конкретного слова, оно остаётся первым.
- Если вакансия просит ссылки на проекты, Generation получает `llm.cover_letter.pet-projects`;
  письмо без ссылки не отправляется, причина пишется в отчёт.

- Дневные отчёты `data/report/<дата>.json` — история вакансий, не удаляются никогда.
  Статусы: `sent`, `skipped`, `queued`, `excluded`, `error`, `rejected`, `offer`.
  `rejected` и `offer` терминальны; `offer` ставится только из `sent`, в UI — с подтверждением.
- Капча не обходится: ожидание `browser.captcha_wait_seconds` и одно письмо о капче.
- Повторы (`--retry`) идут по ссылкам из отчётов без поиска; статусы — `pipeline.retry.statuses`.
- Подъём резюме — не чаще `pipeline.resume.boost_interval_hours`, кэш в `data.paths.cache`.

## Конфигурация

- Формат один: `search` → `pipeline` → `data` → `llm` → `browser` → `notifications`.
- Обязательные разделы: `search` (`queries`, `area`) и `pipeline` (`limit_per_run`,
  `delay_between_actions`). Остальное — дефолты схемы.
- Приоритет: окружение (вложенные ключи через `__`) → `config.local.yaml` → `config.yaml`.
- Личные поля (`llm.cover_letter.signature`) из окружения не читаются.
- Старые плоские ключи не поддерживаются: неизвестный параметр — ошибка при старте.

## Код

- Python 3.11+, только wheels: `playwright`, `httpx`, `ruamel.yaml`, `python-dotenv`,
  `pydantic`, `pydantic-settings`.
- Пакет `agent/`, запуск через `run.py`.
- Русские докстринги и сообщения, `from __future__ import annotations`, frozen-модели.
- Ошибки: `PlaywrightError`, `SessionLostError`, `LLMError`, `ConfigError`.
- Модули: `config`, `browser`, `hh_search`, `hh_vacancy`, `llm`, `prompts`, `pipeline`,
  `processed`, `resume`, `report`, `notify`, `logging_setup`, `profile`, `cli`.
- Веб-интерфейс `web/` — отдельное приложение, агент от него не зависит.

## Логи

- Консоль: одна строка — одно событие, понятный пользователю текст.
- `logs/<дата>.jsonl`: `run_id`, событие, вакансия, причины, вероятности, длины.
  Текста письма и личных данных нет.
- `data.logs_retention_days` чистит только логи; отчёты остаются навсегда.

## Тесты и проверки

- Перед завершением: `pytest -q` и `pyflakes agent run.py tests` без замечаний.
- Новая логика — новый тест. Сеть — `httpx.MockTransport`, браузер не запускается.
- Тесты конфига — таблицами `parametrize`: дефолты, ошибки, приоритет источников.
- Существующие тесты не меняются: упавший тест — регрессия, исправляется код, а не тест.
  Новые тесты — только на новый функционал или исправление бага.

## Окружение

- Windows: `py` / `.venv\Scripts\python.exe`, `run.bat`; bash/WSL — `sh run.sh`.
- Коммиты делает пользователь. Агент не коммитит, не меняет `.env` и не печатает секреты.

## Документация

- Код является источником истины, в документации не нужно дублировать то что уже задокументировано в коде

## Границы

- Капчу не обходим, API hh.ru не используем, правила сайта соблюдаем.
- Публичные ключи конфига меняем только явным решением: формат один.
