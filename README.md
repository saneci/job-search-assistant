# hh-agent

Персональный агент автоматических откликов на hh.ru. Работает по требованию: запустил → выполнил цикл →
завершился. Браузерная автоматизация (Playwright + Chromium), оценка вакансий и генерация писем через
LLM (AITUNNEL), отчёт на email.

## Что делает

1. Открывает Chromium и восстанавливает сохранённую сессию hh.ru (при первом запуске — ручной вход).
2. Ищет вакансии по запросам из `config.yaml` с фильтрами (регион, зарплата, опыт, график).
3. Отфильтровывает вакансии по стоп-словам в названии (без LLM).
4. Открывает каждую вакансию, извлекает полный текст описания.
5. Вакансии с тестами, анкетами и внешними формами складывает в `queue.json`.
6. Decision-вызов LLM возвращает вероятность «подходит»; отклик отправляется при `P > threshold`.
7. Generation-вызов пишет сопроводительное письмо в стиле пользователя (JSON с валидацией).
8. Нажимает «Откликнуться», вставляет письмо, отправляет отклик (с паузами и дневным лимитом).
9. Формирует отчёт: консоль, `.logs/<run_id>.json` и (опционально) email.

## Установка

Требуется Python 3.11+.

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt   # Windows
# source .venv/bin/activate && pip install -r requirements.txt   # macOS/Linux
.venv\Scripts\python -m playwright install chromium
```

На Windows проще запускать `run.bat`: он сам создаст `.venv`, поставит зависимости и Chromium.

## Настройка

1. Скопируйте `.env.example` в `.env` и укажите `AITUNNEL_API_KEY`.
2. Отредактируйте `config.yaml`:
   - `search_query` — строка или список запросов;
   - `area` — название региона (`Москва`, `Россия`, …) или числовой id hh.ru;
   - `salary_from`, `experience`, `schedule` — необязательные фильтры;
   - `exclude_keywords` — стоп-слова в названии;
   - `daily_limit` — максимум откликов за запуск;
   - `delay_between_actions` — случайная пауза между действиями;
   - `llm.decision` / `llm.generation` — базовые URL, модели и порог решения.
3. Отредактируйте `PROFILE.md`: описание, стек, примеры писем и правила стиля.
   Примеры берутся из подраздела «Примеры», правила — из раздела «Стиль написания сопроводительных писем».

Для отчёта на email включите `notifications.email.enabled: true`, заполните `smtp_host`,
`smtp_port`, `use_ssl`, `sender`, `recipient` и задайте `SMTP_PASSWORD` (и при необходимости
`SMTP_USERNAME`) в `.env`.

## Запуск

```bash
python run.py            # обычный цикл; при отсутствии state.json сначала попросит войти
python run.py --login    # только вход и сохранение сессии
python run.py --config config.yaml
```

или двойной клик по `run.bat`.

Первый запуск открывает браузер: войдите в аккаунт hh.ru вручную и нажмите Enter в консоли.
Сессия сохраняется в `state.json` и восстанавливается при следующих запусках.

## Файлы

| Файл | Назначение |
|---|---|
| `config.yaml` | настройки поиска, LLM и уведомлений |
| `PROFILE.md` | профиль пользователя для LLM |
| `state.json` | cookies + localStorage hh.ru (локально, в git не попадает) |
| `queue.json` | вакансии для ручного прохождения (тесты, анкеты, внешние формы) |
| `.logs/<run_id>.jsonl` | события запуска (JSON Lines) |
| `.logs/<run_id>.json` | детальный отчёт запуска |
| `.logs/<run_id>-error-N.png` | скриншот страницы при ошибке |

Причины попадания в очередь: `test`, `questionnaire`, `external_form`, `empty_cover_letter`, `unknown`.
Если hh.ru показывает капчу, вакансия уходит в очередь с причиной `unknown`, а запуск останавливается.

## Тесты

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
```

Тесты покрывают чистую логику (конфигурация, промпты, разбор ответов LLM, очередь, отчёт) без обращений
к hh.ru и LLM.

## Ограничения

- Приложение не обходит капчу и не работает через API hh.ru.
- Отправка откликов автоматизирована: используйте на свой риск и соблюдайте правила hh.ru.
- Сессионные данные и переписка хранятся только локально; наружу уходят лишь запросы к LLM-провайдеру.
