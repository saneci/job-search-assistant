# Как это работает

1. Открывает браузер и восстанавливает сохранённую сессию hh.ru (при первом запуске — ручной вход).
2. Поднимает резюме в поиске, если с прошлого подъёма прошло `resume.boost_interval_hours` часов
   (по умолчанию 4); отметка — в `data/cache.json`.
3. Ищет вакансии по запросам из `config.yaml` с фильтрами (регион, зарплата, опыт, график).
4. Отсеивает вакансии по стоп-словам в названии (без LLM) и по памяти прошлых запусков.
5. Открывает каждую вакансию и извлекает полный текст описания.
6. Вакансии с тестами, анкетами и внешними формами не откликаются, а попадают в дневной отчёт
   со статусом `queued` и понятной причиной.
7. Decision-вызов LLM возвращает вероятность «подходит»; отклик отправляется при `P > threshold`.
8. Generation-вызов пишет сопроводительное письмо в стиле пользователя (JSON с валидацией).
9. Нажимает «Откликнуться», вставляет письмо и отправляет отклик — с паузами и лимитом за запуск.
10. Формирует отчёт: консоль, дневной JSON и (опционально) письмо на email.

Подробности по форматам — [logs-and-reports.md](logs-and-reports.md), команды — [usage.md](usage.md).

## Гарантии кода

Промпт просит, код проверяет. Эти правила живут в коде и описаны в [AGENTS.md](../AGENTS.md),
раздел «Ключевые понятия»:

- приветствие: если модель не начала письмо со «Здравствуйте!», приложение добавит его само;
- обязательное начало: если вакансия просит начать с конкретного слова («со слова 3PL»), оно остаётся
  первым, а приветствие встаёт сразу после него;
- подпись с контактами (`cover_letter_signature`) добавляется кодом и входит в лимит длины письма;
- Decision важнее Generation: при расхождении вердиктов побеждает Decision.

## Почему два вызова LLM

Один вызов — одна задача: Decision даёт вероятности по критериям из конфига, Generation пишет письмо.
Так порог и критерии меняются в конфиге, не трогая промпт и код, а стоимость каждого вызова остаётся
предсказуемой.
