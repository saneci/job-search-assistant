# Feature: Уведомления на email

## Status

`IN_PROGRESS`

> [!NOTE]

## Goal

- Своевременно пройти капчу и не пропустить момент когда система завешится аварийно по таймауту
- После выполнения обработки вакансий получить сводный отчёт по однуму из каналов:
    - В браузере, если запущен сервер
    - На email, если сервер не запущен

## Requirements

### Email functional requirements

1. Письмо генерируется только для вакансий, которые Decision признал подходящими.
2. Ответ LLM проверяется: невалидный JSON повторяется один раз, затем вакансия получает статус
   ошибки или очередь с причиной.
3. Приветствие и подпись с контактами гарантируются кодом. Если вакансия требует начать письмо
   с конкретного слова, оно остаётся первым.
4. Письмо содержит только факты из профиля: опыт, технологии, проекты и числа не выдумываются.
5. Если вакансия просит ссылки на проекты, письмо обязано их содержать. Ссылки берутся из профиля
   или из настроек. Иначе отклик не отправляется, а причина попадает в отчёт.
6. Пустое письмо и расхождение вердиктов Generation и Decision не приводят к отправке. Решение
   Decision важнее. Вакансия уходит в очередь с содержательной причиной.
7. Причина отказа или откладывания берётся из ответа LLM или сообщения сайта. Общие заглушки
   используются только там, где реальной причины нет.
8. После отправки агент проверяет подтверждение сайта. Если подтверждения нет, отклик не считается
   отправленным, а причина и скриншот сохраняются для разбора.
