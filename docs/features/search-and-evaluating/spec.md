# Feature: Поиск и оценка вакансий

## Status

`IN_PROGRESS`

## Goal

Находить подходящие вакансии по разным каналам размещения вакансий и не расходовать лимит откликов на неподходящие.

## Requirements

### Functional requirements

1. Запуск одной командой. При первом запуске пользователь входит в аккаунт вручную, далее сессия
   восстанавливается сама.
2. Резюме поднимается в поиске не чаще заданного интервала.
3. Поиск идёт по сохранённым запросам и фильтрам. Агент проходит всю доступную выдачу или столько
   страниц, сколько разрешено настройкой.
4. Вакансии из прошлых запусков и дубликаты выдачи повторно не обрабатываются.
5. Стоп-слова в названии и компании-исключения отсеиваются без LLM. Похожие кириллические и латинские
   буквы считаются одной: «Разработчик С++» с кириллической «С» ловится стоп-словом «C++»
6. Агент читает описание вакансии. Блок «Требования» и его синонимы («Обязательные требования», «Что мы ждём»,
   «Кого ищем») выделяются из тела описания и уходят в Decision отдельным полем: шапка сайта с «Опыт работы»
   не используется. Decision задаёт несколько вопросов «да/нет» об одном state: есть ли обязательное требование
   без опыта, существенно ли не хватает опыта, подтверждён ли ключевой стек, есть ли красные флаги. Вероятность
   «подходит» — совпадение стека. Блокер (обязательное требование без опыта, существенная нехватка опыта,
   красные флаги) с вероятностью не ниже `llm.decision.blocker_threshold` отменяет отклик независимо от стека.
   Отклик возможен, только если стек выше порога и блокеров нет. Вероятность ровно на пороге считается
   неподходящей: 0.80 при пороге 0.80 пропускается, в консоли причина «вероятность 0.80 не выше порога 0.80»,
   а в отчёте короткая метка «Не подходит по оценке LLM».
   Описание, отданное работодателем картинками, агент распознаёт отдельным Chat-вызовом до
   Decision, см. [каналы поиска](../search-channels/spec.md).
7. Тесты, анкеты, внешние формы, недоступный отклик и капча автоматически не проходятся: вакансия
   откладывается с понятной причиной. У Habr внешняя форма («Откликнуться у компании») проверяется после
   оценки LLM и Generation: письмо и вердикт остаются в записи отчёта.
8. При капче агент ждёт ручного решения и отправляет уведомление. Если решить не удалось, запуск
   останавливается.
9. Уникальность отклика обеспечивается по ключу: url + profile. Отклик другого профиля не делает вакансию
   пройденной для текущего профиля.
10. Если hh.ru показывает кнопку «Отклик другим резюме» без отметки об отказе, текущим резюме агент не откликается:
    отклик уже есть, поэтому Decision не вызывается, а вакансия сразу получает статус `queued` с причиной
    «Уже отправлен отклик по другому резюме»: ждём ответа по другому резюме, чтобы не спамить работодателя.
    См. [кнопка «Отклик другим резюме»](reference/hh-apply-for-a-job-vacancy-using-a-different-resume.png).
11. Если «Вам отказали» показано вместе с кнопкой «Отклик другим резюме», агент открывает форму отклика и смотрит список
    резюме: текущее резюме есть в списке — откликается им (статус `sent`), нет — по текущему резюме уже был отклик,
    вакансия получает статус `rejected` с причиной «По отклику пришёл отказ». Запуск при этом не останавливается.
12. Если hh.ru показывает «Вас пригласили», текущим резюме агент не откликается: вакансия идёт в отчёт со статусом
    `skipped` и причиной «Уже получено приглашение на интервью по другому резюме», а записи другого резюме по этой
    вакансии со статусом `sent` ставится статус `invite`.
    См. [отметка «Вас пригласили»](reference/hh-already-invited.png).
13. Если hh.ru открывает экран «Вам недоступна эта вакансия» (резюме заблокировано или вакансия закрыта для просмотра),
    агент не пытается откликнуться: вакансия идёт в отчёт со статусом `skipped` и причиной «Вакансия недоступна или
    заблокирована», `updated_at` записи — время этой обработки.
    См. [экран «Вам недоступна эта вакансия»](reference/hh-job-opening-is-not-available.png).
14. Если сайт показывает экран «Вакансия в архиве» или доступ к вакансии закрыт, вакансия получает признак
    `archived` в дневном отчёте. Новая вакансия записывается со статусом `skipped` и причиной «Вакансия в
    архиве, работодатель, больше не принимает отклики на эту вакансию». У вакансии, которая уже есть в
    отчётах, статус не меняется, иначе разойдутся метрики и сводка: обновляются признак, причина архива и
    `updated_at`. Экран архива распознаётся и на hh.ru, и на Habr Career: это пропуск, а не ошибка разбора.
    См. [вакансия в архиве](reference/hh-archive-vacancy.png).
15. У настоящего отклика в отчёте короткая причина «Отклик отправлен», а вердикт Generation пишется в
    `message` и виден в окне деталей: по нему понятно, чем отклик обоснован. Последнее предложение
    сопроводительного письма причиной не считается, это стиль письма.
    У уже отправленного ранее отклика причина остаётся «отклик уже отправлен».
    Если форма отклика готова и кнопка отправки активна, подсказка hh.ru о видимости резюме причиной не
    считается даже когда она лежит в явном блоке уведомления
16. Попытка отклика пишется в журнал по шагам: `respond_state.steps` хранит состояние формы, выбранного
    резюме, анкеты, сопроводительного письма, кнопки отправки и ожидания подтверждения. Если отклик не
    прошёл, шаги попадают в `message` записи и открываются в окне деталей: по ним видно, что именно не
    нашлось или не сработало, без чтения DOM и разбора скриншота. Скриншот проблемы пишется событием
    `screenshot` с `vacancy_id`, чтобы было понятно, к какой вакансии он относится. Полный вердикт LLM
    в консоли печатается, но в журнал второй раз не дублируется
17. Ошибка Playwright на клике по кнопке отклика не обрывает попытку: клик повторяется, затем агент ждёт
    форму и продолжает отклик, если она открылась. Текст ошибки клика сохраняется в шагах диагностики.
    Клик ждём `CLICK_TIMEOUT_MS` (10 секунд), а не стандартные 30: иначе страница «дёргается»
    автопрокруткой, а отклик простаивает
18. Неоткрывшийся список резюме — сбой сайта, а не отказ работодателя: вакансия откладывается с причиной
    «hh.ru не открыл список резюме — нужен ручной отклик». Статус `rejected` ставится, только когда
    список открылся и текущего резюме в нём нет
19. Кнопка отклика ищется только у открытой вакансии: кнопки «Откликнуться» из блока «Вам подойдут эти
    вакансии» отбрасываются. Основной признак — `data-qa`: у кнопок вакансии и её формы префикс
    `vacancy-response`, у карточек выдачи и рекомендаций — `vacancy-serp`. Для кнопок без `data-qa`
    проверяется заголовок вакансии в ближайших предках: ссылка на другую вакансию раньше заголовка значит
    чужую карточку. Если у самой вакансии кнопки нет, вакансия откладывается в ручные, а отклик по чужой
    карточке не отправляется. В шагах диагностики пишется подпись и `data-qa` нажатой кнопки

### Limitations

- Кнопка отклика ищется по подписи, `data-qa` и ссылке на другую вакансию в шести ближайших родительских
  блоках. Если hh.ru переименует префиксы `vacancy-response` и `vacancy-serp`, фильтр перестанет различать
  карточки: меняются константы `_VACANCY_TITLE_DEPTH` и префиксы в `_belongs_to_current_vacancy`
- При авторизации на Хабр Карьера проверка кнопки по селектору `.user-auth-menu` зависит от класса шапки Habr. Если Habr
  переименует класс, вход снова станет неверным. План: при смене вёрстки обновить только селектор, бизнес-правило не
  меняется.
- Кнопка «Отклик другим резюме» ищется по тексту `OTHER_RESUME_RE` в `agent/hh_vacancy.py`. Если hh.ru переименует
  кнопку, меняется только этот шаблон, бизнес-правило не меняется.
- Резюме из `pipeline.resume.name` отсутствует в выпадающем списке формы отклика только в двух случаях: резюме удалено
  или этим резюме уже отправлен отклик на вакансию. Агент не выбирает резюме наугад и завершает запуск с событием
  `resume_not_found`. Исключение — форма, открытая кнопкой «Отклик другим резюме»: там отсутствие резюме означает уже
  отправленный отклик, вакансия получает статус `rejected`, а запуск продолжается.
- Отметка «Вас пригласили» терминальна: приглашение работодателя не переотправляется. hh.ru не указывает, какое
  резюме пригласили, поэтому агент считает приглашение полученным по другому резюме. Если записи другого резюме со
  статусом `sent` по этой вакансии нет, остаётся только `skipped` с причиной, статус `invite` никому не ставится.
- Экран «Вакансия в архиве» ищется по тексту `ARCHIVED_TITLE` в `agent/hh_vacancy.py` и
  `agent/habr_vacancy.py`. Если сайт переименует заголовок, меняется только эта строка, бизнес-правило
  не меняется.
- Экран «Вам недоступна эта вакансия» ищется по тексту `UNAVAILABLE_TITLE` в `agent/hh_vacancy.py`. Если hh.ru
  переименует заголовок, меняется только эта строка, бизнес-правило не меняется. Тот же экран hh.ru показывает, когда
  пользователь не авторизован: если после такой вакансии повторный вход не требуется, вакансия остаётся пропущенной,
  поэтому при массовых пропусках с этой причиной нужно проверить сессию.
- Пауза `pipeline.delay_between_actions` выполняется перед обработкой новой вакансии и перед отправкой отклика:
  человек сначала читает вакансию и оценивает её, потом пишет письмо и отправляет. Паузы после отправки нет.
  Пропуски по стоп-словам, архив, приглашение, чужой отклик и отказ паузу не ждут, в `--retry` пауза выполняется
  перед оценкой каждой вакансии.
- Если hh.ru не закроет форму отклика после отправки, агент ждёт до `RESPONSE_RESULT_WAIT_SECONDS` (15 секунд) и только
  потом ставит `queued` с причиной «hh.ru не подтвердил отправку»: старый текст об отклике другого резюме
  подтверждением не считается.
- Живой прогон с двумя резюме на одну вакансию не выполнялся. Проверка ограничена тестами без браузера.

## Acceptance Criteria

- [x] После завершения поиска и обработки вакансий по указанному в конфиге каналу у каждой вакансии есть статус и
  причина
- [x] На подходящие вакансии либо отправлены отклики с сопроводительным письмом, либо есть причина, почему нет
- [x] Лимиты и паузы соблюдены
- [x] Дедубликация работает по составному ключу [отчёта](../report/spec.md): `(url, profile)`
- [x] Если по вакансии уже есть отклик другого резюме (кнопка «Отклик другим резюме»), текущее резюме не откликается:
  вакансия сразу получает `queued` с причиной «Уже отправлен отклик по другому резюме», Decision не вызывается
- [x] Отказ «Вам отказали», показанный вместе с кнопкой «Отклик другим резюме», ведёт к форме отклика: текущее резюме
  есть в списке — отклик уходит (статус `sent`), нет — статус `rejected`
- [x] Если hh.ru показывает «Вас пригласили», текущее резюме пропускается, а записи другого резюме по этой вакансии
  ставится статус `invite`
- [x] Экран «Вам недоступна эта вакансия» даёт статус `skipped` с причиной «Вакансия недоступна или заблокирована» и
  обновлённый `updated_at`
- [x] Архивным вакансиям автоматически добавляется `archived: true` с причиной «Вакансия в архиве,
  работодатель, больше не принимает отклики на эту вакансию»
- [x] У вакансии, которая уже есть в отчётах, экран архива не меняет статус — обновляются признак `archived`,
  причина архива и `updated_at`
- [x] Экран «Вакансия в архиве» на Habr Career даёт пропуск с признаком архива, а не статус `error`
- [x] Вероятность ровно на пороге (0.80 при пороге 0.80) пропускается, отклик не отправляется
- [x] Блокер с вероятностью не ниже `llm.decision.blocker_threshold` отменяет отклик даже при высоком стеке
- [x] Совпадение стека выше порога при небольшой нехватке опыта (до двух лет) отклик не блокирует
