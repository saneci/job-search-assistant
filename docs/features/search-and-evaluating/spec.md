# Feature: Поиск и оценка вакансий

## Status

`IN_PROGRESS`

## Goal

Находить подходящие вакансии по разным каналам размещения вакансий и не расходовать лимит откликов на неподходящие.

## Requirements

### Functional requirements

1. Запуск одной командой. При первом запуске пользователь входит в аккаунт вручную, далее сессия
   восстанавливается сама.
2. Резюме поднимается в поиске не чаще заданного интервала.
3. Поиск идёт по сохранённым запросам и фильтрам. Агент проходит всю доступную выдачу или столько
   страниц, сколько разрешено настройкой.
4. Вакансии из прошлых запусков и дубликаты выдачи повторно не обрабатываются.
5. Стоп-слова в названии и компании-исключения отсеиваются без LLM.
6. Агент читает описание вакансии. Decision оценивает соответствие профилю. Отклик возможен только
   при вероятности выше порога.
7. Тесты, анкеты, внешние формы, недоступный отклик и капча автоматически не проходятся: вакансия
   откладывается с понятной причиной.
8. При капче агент ждёт ручного решения и отправляет уведомление. Если решить не удалось, запуск
   останавливается.
9. Уникальность отклика обеспечивается по ключу: url + profile. Отклик другого профиля не делает вакансию
   пройденной для текущего профиля.
10. Если от текущего профиля (`pipeline.resume.name`, ключ url + profile) отклика ещё не было, а hh.ru показывает кнопку
    «Отклик другим резюме» (отклик уже отправлен другим резюме или по нему пришёл отказ), агент нажимает эту кнопку и
    откликается текущим резюме.
    См.[кнопка «Отклик другим резюме»](apply-for-a-job-vacancy-using-a-different-resume.png).

### Limitations

- При авторизации на Хабр Карьера проверка кнопки по селектору `.user-auth-menu` зависит от класса шапки Habr. Если Habr
  переименует класс, вход снова станет неверным. План: при смене вёрстки обновить только селектор, бизнес-правило не
  меняется.
- Кнопка «Отклик другим резюме» ищется по тексту. Если hh.ru переименует кнопку, меняется только шаблон текста,
  бизнес-правило не меняется.
- Резюме из `pipeline.resume.name` отсутствует в выпадающем списке формы отклика только в двух случаях: резюме удалено
  или этим резюме уже отправлен отклик на вакансию. Агент не выбирает резюме наугад и завершает запуск с событием
  `resume_not_found`.
- Отметка «Вас пригласили» остаётся терминальной: приглашение работодателя другим резюме не переотправляется.
- Живой прогон с двумя резюме на одну вакансию не выполнялся. Проверка ограничена тестами без браузера.

## Acceptance Criteria

- [x] После завершения поиска и обработки вакансий по указанному в кофиге каналу у каждой вакансии есть статус и причина
- [x] На подходящие вакансии либо отправлены отклики с сопроводительным письмом, либо есть причина, почему нет
- [x] Лимиты и паузы соблюдены
- [ ] После выоплнения программы с разными резюме для одной и той же вакансии на
  странице https://hh.ru/applicant/negotiations естть 2 отклика на одну и туже вакансию разными резюме
- [ ] Дедубликация работает по составному ключу [отчёта](../report/spec.md): `(url, profile)`
- [ ] Если другим резюме уже отправлен отклик, текущий профиль обрабатывает вакансию, а не пропускает её
- [ ] Отклик по кнопке «Отклик другим резюме» уходит резюме из `pipeline.resume.name`
- [ ] Отказ «Вам отказали» по отклику другого резюме не останавливает отклик текущим резюме
- [ ] Сквозные критерии выполнены на каждом канале: [каналы поиска](../search-channels/spec.md)
