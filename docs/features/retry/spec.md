# Feature: Повторная обработка вакансий

## Status

`IN_PROGRESS`

## Goal

Повторять вакансии из дневных отчётов по прямой ссылке, не проходя выдачу заново, и явно выбирать канал
запуска, не правя конфиг ради одного прогона.

## Requirements

### Functional requirements

1. `--retry` повторяет вакансии со статусами `pipeline.retry.statuses` (без значения) или с указанным
   статусом, поиск и выдача не используются.
2. Один запуск работает с одним каналом: поведение не меняется, параллельной обработки двух сайтов нет.
3. Канал запуска выбирается необязательным флагом `--channel` с коротким псевдонимом `--ch`.
   Допустимые значения: `hh` и `habr`.
4. Без флага канал берётся из `search.channel`. Дефолт схемы остаётся `hh`: конфиг — единственное
   место, где живёт значение по умолчанию.
5. Флаг действует одинаково для обычного запуска, для `--retry` и для `--login`: выбранный канал
   определяет сессию, браузерный профиль, выдачу, селекторы страницы вакансии и тексты причин.
6. Записи другого канала при повторе пропускаются с понятным сообщением, как сейчас. Счётчики и отчёт
   не меняются.
7. Неверное значение флага — ошибка разбора аргументов до запуска браузера.
8. В логе видно выбранный канал и источник выбора: флаг или конфиг.

### Limitations

- Смешанный повтор (оба канала за один запуск) не входит в эту задачу: это отдельная доработка
  с последовательными сессиями.
- Флаг не переписывает записи отчёта и их поле `channel`.
- Флаг не влияет на `--install-browser` и `--notify-test`: они не связаны с каналом поиска.
- Публичные ключи конфига не меняются, новый ключ не добавляется.

## Acceptance Criteria

- [ ] `--retry --ch habr` повторяет записи career.habr.com, записи hh.ru пропускает
- [ ] `--ch hh` при `search.channel: habr` работает так же, как обычный запуск hh.ru
- [ ] Без флага поведение совпадает с текущим: канал из `search.channel`
- [ ] `--login --ch habr` открывает career.habr.com и сохраняет сессию Habr
- [ ] `--ch superjob` завершается ошибкой аргументов, браузер не запускается
- [ ] Выбранный канал используется на всех шагах: сессия, выдача, страница вакансии, причины
- [ ] В логе есть событие с выбранным каналом и источником выбора
- [ ] Тесты CLI и pipeline на фейковом канале проходят без браузера
