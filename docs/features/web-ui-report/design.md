# Design: Веб-отчёт по вакансиям

Раздел фиксирует решения по интерфейсу отчёта, которых не видно в коде: какие варианты рассматривались,
что выбрано и что отложено.

## Фильтр отчёта: статус и источник

**Задача.** Пользователь отбирает вакансии сразу по двум условиям: статус обработки и сайт, с которого
пришла вакансия. Условия должны складываться, а выбранное состояние — переживать обновление страницы.

### Рассмотренные варианты

| Вариант                   | Как выглядит                  | Решение                            |
|---------------------------|-------------------------------|------------------------------------|
| Грани в один ряд          | «Статус» и «Источник» рядом   | Заменено: меню, см. ниже           |
| Отдельные строки          | Две строки друг под другом    | Отклонено: лишняя высота           |
| Совмещённые значения      | «Habr Career · Отправлено»    | Отклонено: вариантов слишком много |
| Мультивыбор чекбоксами    | Несколько значений в грани    | Отложено, см. раздел ниже          |
| Матрица статус × источник | Тепловая карта вместо фильтра | Отклонено: дублирует метрики       |
| Два выпадающих списка     | Нативные `select`             | Отклонено: лишние клики            |

### Правила выбора

- Внутри грани статуса и источника выбран ровно один вариант, «Все» снимает ограничение грани. Мультивыбор
  статусов отложен, см. ниже, у дат он есть.
- Условия разных граней складываются по «И».
- Активный вариант отмечен галочкой в меню и подтверждается скринридером.
- Поиск по названию, компании, причине и ссылке работает вместе с гранями.
- Пустой результат объясняется словами, кнопка сброса стоит первой в линии фильтров.
- Кнопка сброса видна всегда и становится активной, как только выбран статус, источник или введён поиск.
- «В архиве» — отдельный пункт грани статуса: у архивной вакансии в записи остаётся прежний статус,
  поэтому её показывают только по признаку, а не по статусу.
  Так её место на экране не меняется, а неактивный вид объясняет, что сбрасывать пока нечего.

### Панель фильтров в одну линию

Кнопки-грани с восемью статусами и пятью источниками занимали две строки и меняли высоту
при переносе. Панель переведена на выпадающие меню в стиле фильтра «Резюме» на странице метрик:
кнопка с подписью выбранного значения и меню с галочкой у активного пункта.

- Порядок в линии: «Сбросить фильтры», «Дата», «Статус», «Источник», поиск, счётчик «Показано N из N».
- Ширины кнопок фиксированы, длинное значение обрезается многоточием, поэтому после выбора
  разметка не сдвигается.
- «Дата» — меню с пунктами, как у статуса и источника: выбор идёт по нескольким дням, у каждого дня своя
  галочка, «Выбрать всё» ставит и снимает отметки у всех дней сразу.
- Даты выбираются накопительно, как резюме на странице метрик: клик по дню только отмечает его, меню остаётся
  открытым, а отчёт перезагружается один раз — при закрытии меню. Иначе каждый клик перезагружал бы страницу
  и меню закрывалось бы вместе с ней.
- Открыт может быть только один список, клик вне панели и Escape закрывают его.
- Если мышь ушла с меню и его кнопки, а пункт не выбран, список закрывается сам. Иначе после просмотра списка
  приходится кликать в свободное поле страницы.
- Прокрутка меню идёт во внутренней области, а не в самой панели: полоса прокрутки не заходит на скругление,
  поэтому правые углы остаются такими же круглыми, как левые.
- В Chromium полоса прокрутки тонкая и без кнопок: её задают псевдоэлементы `::-webkit-scrollbar`. Стандартные
  `scrollbar-width` и `scrollbar-color` отключают эти правила и возвращают классическую полосу с кнопками, которая
  закрывает правые скругления. Для Firefox тонкая полоса задаётся этими свойствами внутри
  `@supports not selector(::-webkit-scrollbar)`.
- Счётчик имеет постоянную ширину: тексты «Показано 7 из 1338» и «Показано 1338 из 1338»
  не должны сдвигать поле поиска.

### Сохранение состояния

Источник истины — адрес страницы. Параметры `status`, `channel`, `q` и `date` описывают всё состояние,
поэтому ссылку можно открыть заново и получить тот же отчёт. Последнее состояние дополнительно хранится
в браузере: фильтры не теряются при возврате на отчёт из других страниц. Порядок восстановления — адрес,
затем сохранённое состояние, затем значения по умолчанию. Даты, которых больше нет в отчётах,
отбрасываются.

## Статус в строке: своё меню вместо нативного списка

**Задача.** Статус вакансии меняется прямо в таблице. Нативный `<select>` браузер рисует по-своему: список
открывается системным окном с прямыми углами, и он не похож на меню фильтров.

**Решение.** В ячейке статуса стоит кнопка с тем же оформлением, что и раньше, а по клику открывается меню
в стиле фильтров: скруглённые углы, галочка у активного пункта, недоступные пункты приглушены.

- Меню висит на `body` с позицией `fixed`: таблица прокручивается по горизонтали и обрезала бы вложенный
  список. Позиция считается от кнопки, при нехватке места внизу меню открывается вверх.
- Список прокручивается внутри `.dropdown-scroll`: все статусы, включая «В архиве», доступны, а полоса
  прокрутки не срезает скругление панели. Высота меню вмещает девять статусов без прокрутки, на низком
  экране остаётся прокрутка
- Текущий статус в меню недоступен, оффер доступен только после «Отправлено».
- «В архиве» терминальный: у архивной записи меню не открывается, а API отклоняет смену статуса.
- Подтверждение терминального статуса объясняет последствия: у отказа и оффера меняются статус и причина, у
  архива статус остаётся, причина становится архивной, а вернуть запись в работу нельзя
- Меню закрывается кликом вне, Escape, прокруткой страницы и изменением размера окна. Прокрутка внутри самого
  меню его не закрывает: иначе список статусов нельзя было бы долистать. Если мышь ушла с меню и его кнопки, а
  пункт не выбран, меню закрывается само.

## Отложено: мультивыбор внутри грани

**Что это.** В грани можно отметить несколько значений, например «Отправлено» и «В очереди». Внутри
грани значения складываются по «ИЛИ», между гранями по-прежнему «И».

**Зачем.** Сценарий «покажи всё, что ещё живо»: очередь, ошибки и отправленные без ответа одним взглядом.
Сейчас такой отчёт собирается несколькими переключениями статуса.

**Почему отложено.** Восемь статусов с отметками делают ряд плотным, а одиночный выбор проще объяснить
и проверить. Пока сценарий закрывается фильтром по датам и сводными карточками.

**Что потребуется при реализации.**

- Состояние грани становится списком значений, пустой список означает «без ограничения».
- «Все» очищает список значений этой грани и не влияет на соседнюю грань.
- В адресе страницы значения передаются повтором параметра или через запятую, формат фиксируется
  в коде и в спецификации.
- Кнопка сброса возвращает обе грани к «Все».
- Поведение при пустом результате не меняется: объяснение и кнопка сброса остаются на месте.
- Тест на разметку: у каждой грани есть режим множественного выбора.

У дат мультивыбор уже есть: он нужен, чтобы сравнить несколько дней подряд.

## Реализация

Разметка и логика фильтров — в шаблоне страницы отчёта, общие стили граней и кнопки сброса — в общих
стилях веб-интерфейса. Пункты меню лежат во внутренней области `.dropdown-scroll`, поэтому полоса прокрутки
не срезает скругление панели. Меню статуса в строке собирается в шаблоне и живёт на `body`.
