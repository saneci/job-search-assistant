# Feature: Отчёт об обработанных вакансиях

## Status

DONE

## Goal

По отчёту понимать результат запуска без чтения логов.

## Requirements

### Functional requirements

1. В консоли печатается краткий итог: сколько обработано, отправлено, пропущено, отложено, ошибок.
2. Дневной отчёт `data/report/<дата>.json` не удаляется. Уникальность записи определяется парой `(url, profile)`: одна и
   та же вакансия может иметь отдельные записи для разных профилей и не считается дублем. При обновлении запись
   переносится в отчёт текущей даты, `created_at` не меняется.
3. Технический журнал `logs/<дата>.jsonl` хранит события и причины. Текст письма, профиль и контакты в него не попадают.
   Срок хранения журналов ограничен.
4. Отчёт и уведомления о капче могут отправляться на email.
5. `vacancies.channel: external` у вакансий для отклика на которые требуется перейти на сайт компании.
    1. На Хабре у таких вакансий имя кнопки для отклика: `Откликруться у компании`.
6. `summary` пересчитывается при каждом сохранении отчёта и совпадает с фактическим содержимым `vacancies`.

#### Поля дневного отчёта:

| Объект   | Поле                   | Смысл                           | Логика работы                     | Реализован |
|----------|------------------------|---------------------------------|-----------------------------------|------------|
| Отчёт    | `date`                 | дата, за которую собран отчёт   |                                   | да         |
| Отчёт    | `updated_at`           | время последнего обновления     | обновляется при каждом сохранении | да         |
| Отчёт    | `summary`              | количество вакансий по статусам |                                   | да         |
| Вакансия | `vacancies.url`        | ссылка, название, компания      |                                   | да         |
| Вакансия | `vacancies.title`      | ссылка, название, компания      |                                   | да         |
| Вакансия | `vacancies.company`    | ссылка, название, компания      |                                   | да         |
| Вакансия | `vacancies.status`     | текущий статус                  |                                   | да         |
| Вакансия | `vacancies.attempts`   | сколько раз обрабатывали        |                                   | да         |
| Вакансия | `vacancies.profile`    | резюме для откликов, только hh  | pipeline.resume.name              | да         |
| Вакансия | `vacancies.created_at` | дата обработки вакансии         | не меняется никогда               | да         |
| Вакансия | `vacancies.updated_at` | время последнего изменения      | обновляется при каждом изменении  | да         |
| Вакансия | `vacancies.reason`     | причина статуса                 |                                   | да         |
| Вакансия | `vacancies.channel`    | канал поиск работы              |                                   | да         |

#### Статусы вакансии:

| Статус      | Значение                                                        | Реализован |
|-------------|-----------------------------------------------------------------|------------|
| `sent`      | отклик отправлен или уже был отправлен ранее                    | да         |
| `skipped`   | вакансия не подходит, приглашение или нет доступа               | да         |
| `queued`    | нужен ручной отклик: тест, анкета, форма, капча, письмо, ссылки | да         |
| `excluded`  | стоп-слово в названии или компания-исключение                   | да         |
| `error`     | сбой обработки                                                  | да         |
| `interview` | назначили собеседование, терминальный статус                    | нет        |
| `offer`     | оффер. Терминальный статус, только из `sent`                    | да         |
| `rejected`  | работодатель отказал, терминальный статус                       | да         |

#### Каналы поиска работы:

| Канал      | Значение                           |
|------------|------------------------------------|
| `hh`       | https://hh.ru                      |
| `habr`     | https://career.habr.com            |
| `external` | требуется отклик на сайте компании |

### Limitations

- Копии записи по паре `(url, profile)` в старых файлах отчётов схлопываются только при следующем обновлении записи:
  загрузка истории не переписывает файлы, лишние копии лишь считаются в `dropped_copies`.
- Часть старых записей не содержит `profile`, `created_at` или `updated_at`. Для них ключ `(url, profile)` неполный,
  поэтому нужна миграция или ручная проверка.
- Отчёт хранится в `data/report` внутри каталога проекта, а не в пользовательском каталоге
  `platformdirs.user_data_path`.
- История изменений статуса не ведётся: в отчёте видно только текущее состояние записи.
- Старые файлы отчётов не удаляются и не архивируются, поэтому каталог растёт.

## Acceptance Criteria

- [x] Итоги отчёта сходятся с содержимым отчёта
- [x] По каждой неотправленной вакансии есть причина
- [x] История не теряется
- [x] Персональные данные не попадают в логи
- [ ] В исторических отчётах нет дублей по паре `(url, profile)`
- [x] При обновлении записи `created_at` не меняется, запись переносится в отчёт текущей даты
- [x] `summary` пересчитывается после удаления или переноса записей
- [x] `ProcessedStore` хранит и обновляет записи по ключу `(url, profile)`
- [x] `web/metrics.py` дедуплицирует записи по ключу `(url, profile)`, а не только по URL
- [ ] Разные профили на одну вакансию обрабатываются отдельно и не пропускаются
- [ ] Отчёт сохраняется в локальную папку пользователя через
  `platformdirs.user_data_path("ИмяПриложения", ensure_exists=True)` и не зависит от каталога проекта
