# Feature: Отчёт об обработанных вакансиях

## Status

DONE

## Goal

По отчёту понимать результат запуска без чтения логов.

## Requirements

### Functional requirements

1. В консоли печатается краткий итог: сколько обработано, отправлено, пропущено, отложено, ошибок.
   Отклики печатаются двумя строками: «Отправлено откликов за запуск» и «Отправлено откликов за день».
   Второе число берётся из файла дня и совпадает с карточкой «Отправлено» в веб-отчёте
   В итоге печатается идентификатор запуска `run_id` в формате `ГГГГММДДЧЧММСС` (`20261021170519`).
   Если запуск обработал ровно одну вакансию, заголовок называет резюме для hh и вакансию для Habr.
   После заголовка идут строки «Канал поиска» и «Профиль»: они одинаково печатаются в консоли
   и в письме с отчётом
2. Дневной отчёт `<report_dir>/<дата>.json` не удаляется. Уникальность записи определяется парой `(url, profile)`:
   одна и та же вакансия может иметь отдельные записи для разных профилей и не считается дублем.
   Старая копия Habr без профиля относится к профилю, которым вакансию обрабатывали последний раз,
   поэтому отдельной строкой она не висит
3. Технический журнал `<logs_dir>/<дата>.jsonl` хранит события и причины. Текст письма, профиль и контакты в него
   не попадают. Срок хранения журналов ограничен.
4. Отчёт и уведомления о капче могут отправляться на email.
5. `vacancies.channel: external` только у вакансий hh.ru, для отклика на которые требуется перейти на сайт
   компании. У Habr кнопка «Откликнуться у компании» оставляет канал `habr`.
6. `summary` пересчитывается при каждом сохранении отчёта и совпадает с фактическим содержимым `vacancies`.
7. Признак `archived` не меняет статус записи: у архивной вакансии остаётся прежний `status`, поэтому
   `summary` и метрики считают её как раньше. Признак ставят пайплайн на экране «Вакансия в архиве»
   и веб-интерфейс при переводе в «В архиве». Архив терминальный: снять признак нельзя, а причина у такой
   записи всегда одна — «Вакансия в архиве, работодатель, больше не принимает отклики на эту вакансию».
   Архив относится к вакансии целиком: если в отчётах есть архивная копия, повтор её не берёт, а в отчёте
   показывается архивная строка, даже когда рядом осталась копия без признака
8. При загрузке истории из нескольких копий одной записи берётся самая свежая по `updated_at`, даже если
   в файле дня она записана ниже: строки идут в порядке обработки, первая могла быть старой копией
9. Автоматическая сверка Habr со страницей откликов переносит запись в отчёт текущей даты только когда статус
   действительно меняется. Если статус уже совпадает (например, `rejected` → `rejected`), файл не переписывается.
   `created_at` и `attempts` сохраняются, `updated_at` становится временем сверки. Терминальные `rejected` и
   `offer` и архивная запись не переоткрываются. Сверка ищет запись профиля текущего запуска (имя из
   `# PROFILE:`), поэтому находит и новые записи с профилем, и старые копии без него
10. Остановка запуска не теряет вакансию: если запуск прерван во время обработки, вакансия записывается со
   статусом `error` и причиной «Запуск прерван во время обработки вакансии, проверьте вакансию вручную».
   Отклик мог уже уйти, поэтому точный статус не ставится: вакансия попадает в счётчик ошибок, а в журнале
   остаётся событие `interrupted_vacancy`
11. Агент и веб-интерфейс могут писать один файл дня одновременно. Операции чтения-изменения-записи идут
    под файловой блокировкой каталога `<report_dir>`, а временный файл уникален для процесса: правка статуса
    в UI и обработка вакансии не теряют записи друг друга
12. Блок `questionary` в записи есть всегда: список пар `question` и `answer` в порядке вопросов формы.
    Туда попадают ответы, которые агент вычислил, даже если отклик остался за человеком: по отчёту видно,
    что уже заполнено и что нужно дополнить. Если ответов не было, блок — пустой список.
    Блок пишет пайплайн вместе со статусом, источник и правила ответов описаны
    в [спеке анкет](../questionnaire-autofill/spec.md). Правка статуса в веб-интерфейсе блок не меняет
    и не удаляет: правка касается статуса, причины и времени. Ответы — личные данные: в журнал и в письмо
    с отчётом они не попадают.
13. Если анкета осталась в `queued` из-за субъективных вопросов, `reason` короткий:
    «В анкете есть субъективные вопросы от работодателя, на которые требуется ручной ответ».
    Полный текст с формулировкой вопроса и числом вопросов без ответа пишется в `message`.
    Окно деталей показывает его отдельным полем «Подробности».
14. Колонка «Причина» в таблице остаётся плотной: в `reason` пишется короткая метка —
    «Отклик отправлен», «Не подходит по оценке LLM», «Сбой обработки вакансии», а у отложенных
    вакансий короткая причина отклика. Полный вердикт LLM, текст ошибки и пошаговая диагностика
    отклика (форма, резюме, анкета, письмо, кнопка отправки, ожидание подтверждения) пишутся
    в `message` и открываются в окне деталей. Короткая причина — одно предложение, полный вердикт всегда
    пишется в `message`. В журнал эти тексты не дублируются
15. Сопроводительное письмо хранится в записи полем `cover_letter` только у отложенных и упавших вакансий:
    по нему человек отвечает руками. Отправленной вакансии письмо в отчёт не пишем: оверхэд без пользы.
    Правка статуса в веб-интерфейсе поле сохраняет. Текст письма — личные данные: в журнал и письмо с отчётом
    он не попадает
16. Вердикт Decision пишется в запись полями `probability` (итоговая оценка соответствия) и
    `decision_reason`: «Вакансия подходит на 21%, но это ниже требования 80%». Правила оценки и
    объяснение описаны в [решении о вакансии](../vacancy-decision/spec.md). У вакансий без вызова
    Decision полей нет. Объяснение отказа человеческим текстом (дешёвый Chat-вызов при
    `llm.decision.explain_rejections`) пишется в `message` и открывается в окне деталей полем
    «Подробности»

#### Поля дневного отчёта:

| Объект   | Поле                    | Тип              | Логика работы                                                                                             | Реализован |
|----------|-------------------------|------------------|-----------------------------------------------------------------------------------------------------------|------------|
| Отчёт    | `date`                  | data             | дата, за которую собран отчёт                                                                             | да         |
| Отчёт    | `updated_at`            | data and time    | время последнего обновления, обновляется при каждом сохранении                                            | да         |
| Отчёт    | `summary`               | string           | количество вакансий по статусам                                                                           | да         |
| Вакансия | `vacancies.url`         | string           | URL-ссылка на ваканию                                                                                     | да         |
| Вакансия | `vacancies.title`       | string           | название ваканcии                                                                                         | да         |
| Вакансия | `vacancies.company`     | string           | название компании                                                                                         | да         |
| Вакансия | `vacancies.status`      | status enum      | текущий статус вакансии в системе                                                                         | да         |
| Вакансия | `vacancies.attempts`    | int              | сколько раз обрабатывали                                                                                  | да         |
| Вакансия | `vacancies.profile`     | string           | профиль записи: у hh — резюме из pipeline.resume.name, у Habr — имя из заголовка `# PROFILE:`               | да         |
| Вакансия | `vacancies.created_at`  | data and time    | дата обработки вакансии, не меняется никогда                                                              | да         |
| Вакансия | `vacancies.updated_at`  | data and time    | время последнего изменения, обновляется при каждом изменении                                              | да         |
| Вакансия | `vacancies.invited_at`  | data and time    | когда пришло приглашение, ставится один раз, сменой статуса не сбрасывается                               | да         |
| Вакансия | `vacancies.reason`      | string           | короткая причина статуса для таблицы: метка исхода, а у `rejected`, `offer` и архива — текст правки     | да         |
| Вакансия | `vacancies.message`     | string           | полный текст для окна деталей: вердикт Generation, объяснение Decision, описание сбоя или диагностика    | да         |
| Вакансия | `vacancies.cover_letter`| string           | письмо для окна деталей: только у `queued` и `error`, у отправленных не пишется, правка статуса сохраняет | да         |
| Вакансия | `vacancies.channel`     | channel enum     | канал поиск работы                                                                                        | да         |
| Вакансия | `vacancies.archived`    | boolean          | признак «вакансия в архиве»: ставится пайплайном и вручную в UI                                           | да         |
| Вакансия | `vacancies.run_id`      | string           | идентификатор запуска `ГГГГММДДЧЧММСС`, который обработал вакансию: ручная правка статуса его не меняет   | да         |
| Вакансия | `vacancies.questionary` | array of objects | ответы на анкету или тест: пары `question` и `answer`, есть всегда, пустой список если ответов не было    | да         |
| Вакансия | `vacancies.probability` | float            | итоговая оценка соответствия, у вакансий без оценки поля нет                                              | да         |
| Вакансия | `vacancies.decision_reason` | string        | вердикт Decision человеческим языком: оценка и порог, у вакансий без оценки поля нет                      | да         |

#### vacancies.status - статусы вакансии:

| Статус     | Логика работы                                                                  | Реализован |
|------------|--------------------------------------------------------------------------------|------------|
| `sent`     | отклик отправлен (причина — вердикт Generation) или уже был отправлен ранее    | да         |
| `skipped`  | вакансия не подходит, получено приглашение или доступ закрыт                   | да         |
| `queued`   | нужен ручной отклик: тест, анкета, форма, капча, письмо, ссылки, сайт компании | да         |
| `excluded` | стоп-слово в названии или компания-исключение                                  | да         |
| `error`    | сбой обработки                                                                 | да         |
| `invite`   | пригласили на собеседование: переход только из `sent`                          | да         |
| `offer`    | оффер, терминальный статус: переход из `sent` или `invite`                     | да         |
| `rejected` | работодатель отказал, терминальный статус: переход только из `sent`            | да         |

#### vacancies.channel - каналы поиска работы:

| Канал      | Значение                           |
|------------|------------------------------------|
| `hh`       | https://hh.ru                      |
| `habr`     | https://career.habr.com            |
| `external` | требуется отклик на сайте компании у hh.ru |

### Limitations

- Копии записи по паре `(url, profile)` в старых файлах отчётов схлопываются только при следующем обновлении записи:
  загрузка истории не переписывает файлы, лишние копии лишь считаются в `dropped_copies`. Дубли, накопившиеся к
  2026-10-31, удалены разово, оставшиеся записи переведены в `queued`.
- У записей канала `external` поля `profile` нет: резюме hh.ru к ним не относится. Старые записи Habr без профиля
  при загрузке сопоставляются с именем из `# PROFILE:`, поэтому повторно не обрабатываются, а при следующем
  обновлении схлопываются с копией, у которой профиль уже записан
- Отчёт хранится в каталоге данных пользователя (`platformdirs.user_data_path`), а не в каталоге проекта.
- История изменений статуса не ведётся: в отчёте видно только текущее состояние записи.
- Записи без поля `archived` считаются неархивными: старые файлы отчётов не переписываются.
- Старые архивные записи могли сохранить причину прежнего статуса: веб-интерфейс показывает архивную причину, файлы
  отчётов не переписываются.
- Старые записи с подсказкой hh.ru о видимости резюме показываются с общей причиной
  «Не удалось отправить отклик, посмотрите логи и повторите отправку позже»: файлы
  отчётов не переписываются.
- Старые ответы анкеты очищаются при чтении теми же правилами, что и новые: файлы
  отчётов не переписываются.
- Старые файлы отчётов не удаляются и не архивируются, поэтому каталог растёт.
- У записей старых отчётов поля `run_id` нет: файлы не переписываются, поэтому такие записи
  остаются без идентификатора запуска.

## Acceptance Criteria

- [x] Итоги отчёта сходятся с содержимым отчёта
- [x] По каждой неотправленной вакансии есть причина
- [x] История не теряется
- [x] Персональные данные не попадают в логи
- [x] В исторических отчётах нет дублей по паре `(url, profile)`, а копии записи Habr с профилем и без него
  схлопываются при следующем обновлении
- [x] При обновлении записи `created_at` не меняется, запись переносится в отчёт текущей даты
- [x] `summary` пересчитывается после удаления или переноса записей
- [x] `ProcessedStore` хранит и обновляет записи по ключу `(url, profile)`
- [x] У архивных вакансий в отчёте есть поле `archived`, а `summary` от него не меняется
- [x] У записи с `archived: true` причина про архив, и снять признак нельзя
- [x] Пайплайн не перезаписывает терминальные `rejected` и `offer` и архивную запись карточкой Habr
- [x] Сверка Habr переносит запись в сегодняшний отчёт только при изменении статуса, повторный статус файл не меняет
- [x] Сверка Habr находит записи текущего профиля, а не только старые копии без профиля
- [x] Запись отчёта содержит `run_id` запуска, который её обработал
- [x] Запись с ответами на анкету хранит блок `questionary`, ручная правка статуса его сохраняет
- [x] У `queued` с субъективными вопросами короткий `reason`, полный текст — в `message`
- [x] Ручная правка статуса в веб-интерфейсе не перезаписывает `run_id`
- [x] Ручная правка статуса не переписывает причину, кроме отказа, оффера и архива
- [x] Итог запуска печатает идентификатор запуска и число откликов в файле дня, если оно отличается
- [x] Заголовок отчёта по одной вакансии называет резюме для hh и вакансию для Habr
- [x] В отчёте в консоли и в письме есть канал поиска и профиль запуска
- [x] Остановка запуска во время обработки сохраняет вакансию в отчёт со статусом `error`
- [x] `web/metrics.py` дедуплицирует записи по паре «ссылка и профиль»: разные профили одной вакансии
  считаются отдельно, а старая копия Habr без профиля относится к профилю последней обработки
- [x] Повтор не берёт вакансию, у которой в отчётах есть архивная копия
- [x] В отчёте показывается архивная строка вакансии, даже если рядом осталась копия без признака
- [x] Разные профили на одну вакансию обрабатываются отдельно и не пропускаются
- [x] Письмо хранится в `cover_letter` у отложенных и упавших вакансий и не удаляется при правке статуса
- [x] Habr с кнопкой «Откликнуться у компании» остаётся каналом `habr`, `external` ставится только у hh.ru
- [x] Отчёт сохраняется в локальную папку пользователя через
  `platformdirs.user_data_path("job-search-assistant", appauthor=False, ensure_exists=True)` и не зависит
  от каталога проекта
