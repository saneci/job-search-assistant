# Feature: Отчёт об обработанных вакансиях

## Status

DONE

## Goal

По отчёту понимать результат запуска без чтения логов.

## Requirements

### Functional requirements

1. В консоли печатается краткий итог: сколько обработано, отправлено, пропущено, отложено, ошибок.
2. Дневной отчёт `data/report/<дата>.json` не удаляется. Уникальность записи определяется парой `(url, profile)`: одна и
   та же вакансия может иметь отдельные записи для разных профилей и не считается дублем.
3. Технический журнал `logs/<дата>.jsonl` хранит события и причины. Текст письма, профиль и контакты в него не попадают.
   Срок хранения журналов ограничен.
4. Отчёт и уведомления о капче могут отправляться на email.
5. `vacancies.channel: external` у вакансий для отклика на которые требуется перейти на сайт компании.
    1. На Хабре у таких вакансий имя кнопки для отклика: `Откликруться у компании`.
6. `summary` пересчитывается при каждом сохранении отчёта и совпадает с фактическим содержимым `vacancies`.
7. Признак `archived` не меняет статус записи: у архивной вакансии остаётся прежний `status`, поэтому
   `summary` и метрики считают её как раньше. Признак ставят пайплайн на экране «Вакансия в архиве»
   и веб-интерфейс при переводе в «В архиве». Архив терминальный: снять признак нельзя, а причина у такой
   записи всегда одна — «Вакансия в архиве, работодатель, больше не принимает отклики на эту вакансию».
8. Автоматическая сверка Habr со страницей откликов переносит запись в отчёт текущей даты только когда статус
   действительно меняется. Если статус уже совпадает (например, `rejected` → `rejected`), файл не переписывается.
   `created_at` и `attempts` сохраняются, `updated_at` становится временем сверки. Терминальные `rejected` и
   `offer` и архивная запись не переоткрываются.

#### Поля дневного отчёта:

| Объект   | Поле                   | Тип           | Логика работы                                                               | Реализован |
|----------|------------------------|---------------|-----------------------------------------------------------------------------|------------|
| Отчёт    | `date`                 | data          | дата, за которую собран отчёт                                               | да         |
| Отчёт    | `updated_at`           | data and time | время последнего обновления, обновляется при каждом сохранении              | да         |
| Отчёт    | `summary`              | string        | количество вакансий по статусам                                             | да         |
| Вакансия | `vacancies.url`        | string        | URL-ссылка на ваканию                                                       | да         |
| Вакансия | `vacancies.title`      | string        | название ваканcии                                                           | да         |
| Вакансия | `vacancies.company`    | string        | название компании                                                           | да         |
| Вакансия | `vacancies.status`     | status enum   | текущий статус вакансии в системе                                           | да         |
| Вакансия | `vacancies.attempts`   | int           | сколько раз обрабатывали                                                    | да         |
| Вакансия | `vacancies.profile`    | string        | резюме для откликов, только для канала hh: pipeline.resume.name             | да         |
| Вакансия | `vacancies.created_at` | data and time | дата обработки вакансии, не меняется никогда                                | да         |
| Вакансия | `vacancies.updated_at` | data and time | время последнего изменения, обновляется при каждом изменении                | да         |
| Вакансия | `vacancies.invited_at` | data and time | когда пришло приглашение, ставится один раз, сменой статуса не сбрасывается | да         |
| Вакансия | `vacancies.reason`     | string        | причина статуса, заполняется всегда: у `sent` — последнее предложение письма LLM или «отклик уже отправлен» | да         |
| Вакансия | `vacancies.channel`    | channel enum  | канал поиск работы                                                          | да         |
| Вакансия | `vacancies.archived`   | boolean       | признак «вакансия в архиве»: ставится пайплайном и вручную в UI            | да         |

#### Статусы вакансии:

| Статус     | Логика работы                                                           | Реализован |
|------------|-------------------------------------------------------------------------|------------|
| `sent`     | отклик отправлен (причина — последнее предложение письма) или уже был отправлен ранее | да         |
| `skipped`  | вакансия не подходит, получено приглашение или доступ закрыт            | да         |
| `queued`   | нужен ручной отклик: тест, анкета, форма, капча, письмо, ссылки, сайт компании | да    |
| `excluded` | стоп-слово в названии или компания-исключение                           | да         |
| `error`    | сбой обработки                                                          | да         |
| `invite`   | пригласили на собеседование: переход только из `sent`                   | да         |
| `offer`    | оффер, терминальный статус: переход из `sent` или `invite`              | да         |
| `rejected` | работодатель отказал, терминальный статус: переход из `sent` и `invite` | да         |

#### Каналы поиска работы:

| Канал      | Значение                           |
|------------|------------------------------------|
| `hh`       | https://hh.ru                      |
| `habr`     | https://career.habr.com            |
| `external` | требуется отклик на сайте компании |

### Limitations

- Копии записи по паре `(url, profile)` в старых файлах отчётов схлопываются только при следующем обновлении записи:
  загрузка истории не переписывает файлы, лишние копии лишь считаются в `dropped_copies`. Дубли, накопившиеся к
  2026-10-31, удалены разово, оставшиеся записи переведены в `queued`.
- У записей каналов `habr` и `external` поля `profile` нет по устройству канала: резюме hh.ru к ним не относится,
  поэтому ключ `(url, profile)` для них совпадает с URL.
- Отчёт хранится в `data/report` внутри каталога проекта, а не в пользовательском каталоге
  `platformdirs.user_data_path`.
- История изменений статуса не ведётся: в отчёте видно только текущее состояние записи.
- Записи без поля `archived` считаются неархивными: старые файлы отчётов не переписываются.
- Старые архивные записи могли сохранить причину прежнего статуса: веб-интерфейс показывает архивную причину, файлы
  отчётов не переписываются.
- Старые файлы отчётов не удаляются и не архивируются, поэтому каталог растёт.

## Acceptance Criteria

- [x] Итоги отчёта сходятся с содержимым отчёта
- [x] По каждой неотправленной вакансии есть причина
- [x] История не теряется
- [x] Персональные данные не попадают в логи
- [x] В исторических отчётах нет дублей по паре `(url, profile)`
- [x] При обновлении записи `created_at` не меняется, запись переносится в отчёт текущей даты
- [x] `summary` пересчитывается после удаления или переноса записей
- [x] `ProcessedStore` хранит и обновляет записи по ключу `(url, profile)`
- [x] У архивных вакансий в отчёте есть поле `archived`, а `summary` от него не меняется
- [x] У записи с `archived: true` причина про архив, и снять признак нельзя
- [x] Пайплайн не перезаписывает терминальные `rejected` и `offer` и архивную запись карточкой Habr
- [x] Сверка Habr переносит запись в сегодняшний отчёт только при изменении статуса, повторный статус файл не меняет
- [x] `web/metrics.py` дедуплицирует записи по ключу `(url, profile)`, а не только по URL
- [x] Разные профили на одну вакансию обрабатываются отдельно и не пропускаются
- [ ] Отчёт сохраняется в локальную папку пользователя через
  `platformdirs.user_data_path("ИмяПриложения", ensure_exists=True)` и не зависит от каталога проекта
