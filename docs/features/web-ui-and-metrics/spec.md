# Feature: Веб-интерфейс и метрики

## Status

`IN_PROGRESS`

> [!NOTE]
> В разработке, но работает в проде, описание неполное

## Goal

Видеть итоги откликов без разбора логов: что отправлено, что пропущено и почему, где проседает воронка,
и быстро находить нужные вакансии по статусу, источнику и дате.

## Requirements

### Functional requirements

1. Веб-интерфейс работает с дневными отчётами и не требует браузера hh.ru.
2. В отчёте вакансии фильтруются по статусу и по источнику, оба условия действуют одновременно.
3. Поиск идёт по названию, компании, причине и ссылке и работает вместе с фильтрами.
4. Выбранное состояние (статус, источник, даты, текст поиска) сохраняется после обновления страницы
   и воспроизводится ссылкой.
5. Кнопка «Сбросить фильтры» снимает все условия одним нажатием. Кнопка видна всегда, но неактивна,
   пока не выбран статус, источник или текст поиска.
6. Если условия ничего не нашли, интерфейс объясняет пустой результат и предлагает сброс.
7. Терминальные статусы `rejected` и `offer` нельзя сменить без подтверждения. Из `offer` нельзя перейти
   в другой статус.
8. Страница метрик и API показывают воронку и конверсии за год, квартал, месяц, неделю или день.
9. Одна вакансия учитывается один раз — по последней записи. Период воронки считается по
   `created_at`, а не по файлу, в котором сейчас лежит запись.
10. Метрики показывают распределение вакансий по источникам: hh.ru, Habr Career и записи без источника.

Отклики — это `sent`, `rejected` и `offer`. Конверсия в отклик считается от всех вакансий, в оффер —
от откликов.

**Почему по дате создания.** Вакансия остаётся в когорте месяца, когда была обработана.
Если отклик отправлен месяц назад, а ответ пришёл сейчас, вакансия не переезжает в текущий месяц:
меняется только её текущий статус. Это даёт стабильную воронку по когортам. Динамика «сколько
ответов пришло в этом месяце» требует отдельной истории событий и пока не ведётся.

### Limitations

- Поддерживаемые системы: Windows, macOS, Linux.
- Работа только через браузер, без API сайта.
- Живая проверка фильтров в браузере не выполнена: проверены разметка, стили и тесты страницы, ручной
  прогон на реальных отчётах нужен отдельно.
- Внутри грани выбирается одно значение: несколько статусов одновременно не отобрать, мультивыбор отложен
  по решению из `design.md`.
- У значений фильтра нет счётчиков: сколько вакансий в каждом статусе и источнике, видно на странице
  метрик и в сводных карточках.
- Логика фильтров написана на JavaScript и не покрыта автотестами: в проекте нет JS-тест-раннера, тест
  проверяет только разметку страницы.
- Сохранённое состояние живёт в браузере пользователя: после очистки данных браузера остаётся только то,
  что попало в адрес страницы.
- В отчёте нет показа профиля (резюме).

## Acceptance Criteria

- [x] В метриках цифры метрик сходятся с отчётами
- [x] В отчёте пользователь находит нужную вакансию и причину
- [x] В отчёте терминальные статусы защищены от случайного изменения
- [x] Фильтры по статусу и источнику действуют одновременно
- [x] Фильтры, включая дату и поиск, сохраняются после обновления страницы
- [x] Кнопка `Сбросить фильтры` есть всегда, но активна становится только когда выбраны все или один
  из фильтров: `Статус`, `Источник`, `Поиск`
- [x] Кнопка `Сбросить фильтры` возвращает отчёт к полному списку без фильтров
- [x] У кнопки `Сбросить фильтры` стили такие же как у других кнопок блоков `Статус` и `Источник`:
  границы, цвет, шрифт
- [x] После ввода текста в поле `Поиск`
    - [x] Иконка `Лупа` исчезает
    - [x] Справа появляется крестик при наведении мыши на который появляется иконка `Рука`
- [ ] Раздел `/metrics / Судьба отправленных откликов`: на графике отображаются только числа и проценты
