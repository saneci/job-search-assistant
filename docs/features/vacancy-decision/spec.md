# Feature: Решение о соответствии вакансии

## Status

`IN_PROGRESS`

## Goal

Пользователь видит одну понятную оценку «насколько вакансия подходит» и причину словами.
По оценке агент решает, откликаться или пропустить вакансию, а в отчёте видно, почему решение принято.

## Как работает сейчас

1. Decision LLM задаёт четыре вопроса о паре «профиль и вакансия»:
   - есть ли в требованиях обязательное требование, которого нет в профиле
   - существенно ли требуемый опыт в роли выше фактического опыта пользователя
   - подтверждён ли ключевой стек вакансии
   - есть ли в вакансии красные флаги
2. Модель отвечает уверенностью от 0 до 100% по каждому вопросу.
3. Оценка «подходит» — это только уверенность по совпадению стека, остальные три проверки в оценку
   не входят.
4. Блокер — проверка, где «да» означает проблему, с уверенностью не ниже 50%: обязательные требования,
   нехватка опыта и красные флаги.
5. Вердикт Decision: вакансия подходит, если оценка выше 80% и ни один блокер не сработал.
6. Пайплайн вердикт Decision не читает и решает об отклике только по порогу оценки, поэтому вакансия с
   блокером и оценкой выше 80% получает отклик.
7. В «Решение LLM» показывается «Вакансия подходит на 82%, это выше требования 80%».
8. Объяснение модели запрашивается только когда оценка не выше порога, поэтому у вакансии с оценкой выше
   порога «Подробности» остаётся пустым: объяснение не запрашивалось.
9. Объяснение получает обрезанное описание, поэтому требование в конце описания в объяснение не попадает.
10. Критерий «ключевой стек» описан словами «большинство», без числа, поэтому модель сама решает, что
    считать большинством.
11. Критерий «обязательные требования» не запрещает модели считать пункты блока «Обязанности»
    требованиями.
12. Блок «Требования» ищется по заголовкам, но в описаниях hh.ru встречаются заголовки вроде
    «Какие знания и навыки нам важны», которых нет в списке.

## Requirements

### Functional requirements

1. Все четыре вопроса формулируются так, что «да» означает «проблем нет», а «нет» — «проблема есть».
2. Оценка соответствия — одно число от 0 до 100%, которое складывается из четырёх вопросов с весами:
   стек 40%, обязательные требования 30%, опыт 15%, красные флаги 15%.
3. Уверенность по каждому вопросу идёт в оценку напрямую, без инверсии: у вопроса про красные флаги
   «да» значит «флагов нет».
4. Если все четыре вопроса хорошие, оценка равна 100%.
5. Порог соответствия — 80%, оценка ровно на пороге считается неподходящей: вакансия пропускается.
6. Отклик отправляется только по оценке: если оценка выше порога, отклик уходит, отдельного жёсткого
   запрета по отдельным проверкам нет.
7. Веса задаются в конфигурации.
8. «Решение LLM» показывает оценку и порог, как сейчас: «Вакансия подходит на 17%, но это ниже требования
   80%». Названия проверок и их вероятности в отчёт не пишутся, они остаются в журнале.
9. Объяснение запрашивается, когда вакансия не прошла по оценке, и не запрашивается, когда оценка выше
   порога.
10. Критерий «стек»: «Все технологии и обязанности, перечисленные в вакансии, подтверждены профилем».
11. Критерий «обязательные требования»: «Все требования, кроме технологий, подтверждены профилем».
12. Критерий «опыт»: «Опыт в роли не меньше требуемого более чем на два года».
13. Критерий «красные флаги»: «Красных флагов в вакансии нет».
14. Блок «Требования» ищется по заголовкам и синонимам, включая «Какие знания и навыки нам важны» и
    «Что нужно делать».
15. Объяснение получает полный текст описания и отдельный блок «Требования», а не обрезанное начало.
16. Из весов следует: если обязательные требования не подтверждены полностью, оценка не может быть выше
    70% и вакансия пропускается, даже когда остальные вопросы на 100%.
17. Из весов следует: если стек не подтверждён полностью, оценка не может быть выше 60% и вакансия
    пропускается.

### Limitations

- Уверенность модели — не измерение, а самооценка, поэтому оценка 80% не означает, что пользователь
  справится с 80% работы.
- Веса и порог задаются вручную и не калибруются на размеченных вакансиях.
- Модель не перечисляет требования списком, поэтому конкретное требование в «Подробностях» называет
  объяснение, а не сам Decision.
- Состав оценки в отчёте не показывается: видны только итоговое число и порог, вероятности по вопросам
  остаются в журнале.

## Открытые вопросы

Открытых вопросов нет. Технологии относятся к стеку, обязательные требования считаются только по
не-технологиям. Частичное совпадение решает LLM. Оценка ровно на пороге считается неподходящей.

## Acceptance Criteria

- [ ] Оценка складывается из четырёх вопросов, а не только из совпадения стека
- [ ] Все вопросы сформулированы так, что «да» означает «проблем нет»
- [ ] Если все четыре вопроса хорошие, оценка 100%
- [ ] «Решение LLM» показывает оценку и порог, без названий проверок
- [ ] Если обязательные требования не подтверждены полностью, оценка не выше 70%, вакансия пропускается
- [ ] Если стек не подтверждён полностью, оценка не выше 60%, вакансия пропускается
- [ ] В «Подробностях» объяснение называет конкретное требование, а не название проверки
- [ ] Объяснение запрашивается только при оценке не выше порога
