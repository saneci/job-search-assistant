# Feature: Каналы поиска работы

## Status

`DONE`

## Goal

Искать вакансии на нескольких площадках, а не только на hh.ru: один цикл «оценка → письмо → отклик → отчёт» работает для
любого подключённого сайта, поэтому вакансии, опубликованные мимо hh.ru, не теряются.

## Requirements

### Functional requirements

1. Канал выбирается настройкой `search.channel`: `hh` (по умолчанию) или `habr`. Один запуск работает с одним каналом.
2. Правила поиска зависят от канала. На hh.ru вакансии ищутся по сохранённым запросам и региону. На career.habr.com
   поиск по запросам есть, но на текущем этапе развития проекта принято решение реализовать поиск по подходящим: агент
   читает ленту «Подходящие», а глубину ограничивает `search.pages_limit`.
3. Всё, что не зависит от сайта, работает одинаково: оценка LLM-Decision, письмо LLM-Generation, проверки письма,
   лимиты, паузы, дедупликация и дневной отчёт.
4. У каналов раздельные сессии и браузерные профили: вход на один сайт не сбрасывает вход на другой. Ручной вход
   `./run.sh --login` открывает сайт выбранного канала.
5. Капча не обходится. Агент ждёт ручного решения, отправляет одно письмо о капче с названием сайта и останавливает
   запуск, если капчу не решили.
6. Отклик на Habr состоит из двух действий: кнопка создаёт отклик, письмо добавляется к нему отдельно. Письмо готово до
   первого клика, иначе отклик останется без письма. Без подтверждения сайта отклик не считается отправленным.
7. Вакансию с отметкой «Вы откликнулись» агент не открывает: в отчёте она получает статус `sent` с причиной «Отклик уже
   отправлен», а лимит откликов не расходуется. Если вакансия уже есть в отчётах, карточка не меняет её статус, причину,
   попытки и `updated_at`: вакансия просто пропускается. Карточка говорит только о факте отклика и не знает, чем он
   закончился, поэтому терминальный отказ, оффер, приглашение и архив она не откатывает.
8. Отклик, который уходит на сайте компании, автоматически не отправляется. У Habr вакансия с кнопкой
   «Откликнуться у компании» проходит оценку LLM и Generation как обычная: письмо приложено к записи отчёта
   полем `cover_letter`, подходящая вакансия получает статус `queued` с причиной «Отклик нужно отправить
   на сайте компании» и полным вердиктом в `message`, канал отчёта остаётся `habr`. Неподходящая вакансия
   пропускается с причиной «Не подходит по оценке LLM»
9. Подъём резюме есть только на hh.ru, на Habr этот шаг не выполняется.
10. [--retry](../retry/spec.md) идёт по ссылкам из отчётов и определяет канал поиска по ссылке. Если страница требует
    отклик на сайте компании, запись hh.ru получает канал отчёта `external`, а запись Habr остаётся `habr`.
    Записи, которые не относятся к выбранному каналу, пропускаются с понятным сообщением.
11. У каждой записи отчёта есть источник: `hh`, `habr` или `external` у hh.ru. Записи старых отчётов без источника
    показываются отдельно. Фильтр отчёта и метрики учитывают источник.
12. Вход на Habr проверяется по видимой кнопке «Войти» внутри `.user-auth-menu`, а не по контейнеру меню.
    Проверяются все элементы, потому что часть из них скрыта на мобильной вёрстке. Ссылка «Войти» не подходит:
    на Habr это кнопка, поэтому старая проверка считала гостя авторизованным.
13. Сессия Habr хранится в постоянном профиле `data/habr-profile`. Файл `data/habr-state.json` — только копия
    cookie. Если нет ни файла, ни профиля, приложение сразу предлагает ручной вход, не открывая сайт для проверки.
14. Без сессии приложение не открывает выдачу и вакансии: сначала ручной вход. Гостевая форма отклика и её reCAPTCHA
    не используются, это лишние действия и расход ресурсов.
15. Капча, которая не блокирует отклик (например, капча формы гостевого отклика), запуск не останавливает.
    Признаки блокирующей капчи проверяются по адресу страницы и тексту диалога.
16. В конце цикла Habr агент сверяет статусы с `https://career.habr.com/responses`. «Отказ», «Приглашение» и
    «Оффер» уточняют записи, которые уже есть в отчёте, а «Прочитано» и «Не прочитано» означают `sent`. При
    изменении статуса запись переносится в сегодняшний отчёт, а при совпадении статуса файл не переписывается:
    повторный «Отказ» не создаёт новую запись. `created_at` и `attempts` сохраняются, `updated_at` становится
    временем сверки. Терминальные `rejected`, `offer` и архив не переоткрываются. Сверка не создаёт записи и не
    ломает запуск при ошибке.
17. Описание вакансии Habr может состоять только из картинок: текста в блоке описания нет, `alt` у изображений
    пустой. Тогда агент собирает адреса картинок блока описания и переписывает текст с них отдельным Chat-вызовом.
    Распознанный текст заменяет описание и уходит в Decision и Generation. Параметры — `llm.ocr`: выключатель,
    модель (по умолчанию модель Generation), число картинок и предельный вес файла. Если распознавание выключено
    или не удалось, агент собирает альтернативное описание из мета-описания страницы и блоков «Требования» и
    «Условия», а если и их нет — вакансия считается неразобранной. Сбой распознавания запуск не останавливает.
    В журнал попадают число изображений и длина распознанного текста, самого текста в журнале нет.

### Limitations

- hCaptcha рисуется только в постоянном профиле Chrome `data/habr-profile`, поэтому вход на Habr возможен только
  вручную.
- Каналы не смешиваются: за один запуск обрабатывается один сайт.
- Отклики через внешнюю форму на стороне компании не отправляются.
- Статусы Habr читаются со страницы `https://career.habr.com/responses`: в карточке вакансии их нет. Если Habr
  переименует подписи «Отказ», «Приглашение» или «Оффер», меняется только сопоставление в `agent/habr_search.py`
- Сверка Habr не создаёт записи для откликов, которых нет в отчёте, и читает только основную вкладку откликов,
  не «Удалённые»
- На Habr есть поиск по фильтрам запроса, но на текущем этапе сделана упрошённая реализация по "подходящим".

## Acceptance Criteria

- [x] Запуск без `search.channel` работает как раньше - на hh.ru
- [x] `search.channel: habr` читает ленту «Подходящие» без запросов и региона
- [x] Сессии и браузерные профили каналов не пересекаются
- [x] Карточка «Вы откликнулись» не открывается, в отчёте это `sent` с причиной
- [x] Повторная карточка «Вы откликнулись» не меняет запись, которая уже `sent`
- [x] Карточка Habr не откатывает `rejected`, `offer`, `invite` и архивную запись в `sent`
- [x] Вакансия Habr с откликом на сайте компании получает `queued` с причиной «Отклик нужно отправить
  на сайте компании», канал `habr`, письмо и полный вердикт в записи
- [x] Уже известная вакансия Habr с карточкой «Вы откликнулись» просто пропускается
- [x] В конце цикла Habr неархивные записи уточняются по странице откликов, запись переносится в сегодняшний отчёт
  только при изменении статуса
- [x] Терминальные `rejected`, `offer` и архив при сверке Habr не меняются
- [x] Ошибка страницы откликов не прерывает запуск
- [x] У **каждой** записи отчёта есть `channel`, фильтр отчёта и метрики различают источники
- [x] Письмо о капче для Habr называет сайт
- [x] `--retry` пропускает записи другого канала
- [x] Подъём резюме не выполняется на Habr
- [x] Отклик на career.habr.com подтверждается сайтом в живом прогоне
- [x] Отклик с письмом на career.habr.com доходит до адресата
- [x] Вакансия Habr с описанием-картинками получает описание из требований, условий и мета-описания
- [x] На чистом окружении Habr не считает сессию существующей и предлагает ручной вход
- [x] Капча формы гостевого отклика reCAPTCHA на странице вакансии не останавливает залогиненный запуск
