# Feature: Выбор резюме при отклике

## Status

`IN_PROGRESS`

## Goal

Откликаться только тем резюме, которое выбрал пользователь, и не отправлять отклик
от чужого резюме. Если настроенного резюме нет в списке hh.ru, запуск останавливается
с понятной ошибкой, а не отправляет отклик наугад.

## Термины

- **Резюме (`profile`)** — название резюме из `pipeline.resume.name`. В отчёте это поле
  `vacancies[].profile`.
- **Запись вакансии** — элемент `vacancies[]` дневного отчёта. Ключ записи — пара
  `(url, profile)`: ссылка на вакансию и название резюме.
- **Дедупликация** — вакансия считается обработанной для этого резюме, если есть запись
  с тем же ключом. Разные резюме — независимые записи со своим статусом, попытками и причиной.

## Requirements

### Functional requirements

1. На hh.ru модалка отклика открывается после нажатия «Откликнуться», агент работает в области модалки. Если на
   странице есть только кнопка «Отклик другим резюме» без отметки об отказе, агент её не нажимает: отклик по
   вакансии уже есть у другого резюме. Подходящая вакансия получает статус `queued` с причиной «Уже отправлен
   отклик по другому резюме»: ждём ответа по другому резюме, чтобы не спамить работодателя. Если вакансия не
   подходит, она пропускается по причине оценки
2. Если «Вам отказали» показано вместе с кнопкой «Отклик другим резюме», агент нажимает её и открывает форму
   отклика: отказ пришёл по прошлому отклику, поэтому текущим резюме можно откликнуться на эту вакансию. Если
   текущего резюме нет в списке формы, вакансия получает статус `rejected`
3. В модалке агент находит выпадающий список резюме и выбирает нужное
4. Имя целевого резюме — `pipeline.resume.name`. Это же значение пишется в запись отчёта как `vacancies[].profile`,
   поэтому в отчёте видно, каким резюме отправлен отклик. Отдельного ключа конфига `vacancies.profile` нет:
   `vacancies` — массив записей в `data/report/<дата>.json`, `profile` — поле записи
5. Если имя задано и найдено в списке, резюме выбирается до заполнения письма.
6. Если имя задано, но в списке его нет, запуск завершается ошибкой: событие `resume_not_found` с именем резюме и URL,
   сообщение в консоли, код 1. Отклик не отправляется. Исключение — форма, открытая кнопкой «Отклик другим резюме»:
   там отсутствие резюме означает уже отправленный отклик, вакансия получает статус `rejected`, запуск продолжается
7. Параметр `pipeline.resume.name` является обязательным и не может быть пустым, если не заполнено выводим ошибку:
   событие `resume_name_is_empty` и завершаем работу
8. Список резюме ищется устойчиво: по точному тексту, по ролям `combobox`/`listbox`/`option` и по атрибутам `data-qa`,
   содержащим `resume`
9. Выбор резюме не меняет письмо, подпись и порядок шагов отклика
10. Канал `habr` не использует резюме hh.ru: для него поведение не меняется
11. Дедупликация, повтор и метрики работают по паре `(url, profile)`: одним резюме можно
    откликнуться на вакансию, а другим — позже, не теряя первую запись
12. Кастомный список резюме закрывается после выбора: открытый список перекрывает кнопку отправки, и отклик не
    уходит. Если нужное резюме уже выбрано в форме, список не открывается
13. Предупреждение hh.ru «поменяйте видимость резюме» не считается причиной никогда: hh.ru показывает его и при
    открытом резюме. Если сайт не дал другой причины, в отчёт и журнал пишется «Не удалось отправить отклик,
    посмотрите логи и повторите отправку позже»
14. Повтор работает резюме из конфига запуска: резюме из записи отчёта не подставляется. Иначе в форме отклика
    могло не оказаться нужного резюме, и запуск падал бы с `resume_not_found`

### Limitations

- Одно резюме на запуск: чтобы откликнуться другим резюме, поменяйте `pipeline.resume.name`
  и запустите снова
- Точные селекторы hh.ru проверяются живым запуском: при смене вёрстки меняется только слой поиска элементов,
  бизнес-правила остаются
- Резюме не создаётся и не редактируется: агент только выбирает существующее
- Для `habr` выбор резюме не реализуется, поскольку там нет возможности создания нескольких резюме, только единый
  профиль

## Acceptance Criteria

- [x] При отсутствии названия резюме в выпадающем списке модального окна:
    - [x] Запуск завершается кодом 1, отклик не отправляется
    - [x] В логе есть событие `resume_not_found` с именем резюме и URL вакансии
    - [x] В консоли понятное сообщение об ошибке без трейсбека
- [x] При пустом `pipeline.resume.name` на hh.ru завершение работы с ошибкой
  `resume_name_is_empty`, канал `habr` не затронут
- [x] Дедупликация поиска, повторов, метрик и правки статуса идёт по `(url, profile)`
- [x] После выбора резюме кастомный список закрыт, кнопка отправки доступна
- [x] Если нужное резюме уже выбрано, список резюме не открывается
- [x] Подсказка о видимости резюме не попадает в причину, когда кнопка отправки была активна, в том числе
  когда она лежит в явном блоке уведомления формы
- [x] Повтор не подставляет резюме из записи отчёта и не падает на записи другого резюме
- [x] Поле `vacancies[].profile` в отчёте совпадает с выбранным резюме
- [x] Тесты проходят без браузера
- [ ] Живой прогон hh.ru: отклик уходит с выбранным резюме
