# Feature: Автоматическое заполнение анкет и прохождение тестов

## Status

`IN_PROGRESS`

## Goal

Не терять вакансии, где после кнопки «Откликнуться» появляется анкета или тест работодателя. Агент отвечает на
вопросы из профиля и одним вызовом LLM и отправляет отклик без ручного участия. Заодно анкета-отсечка перестаёт
тратить токены: вопрос, ответ на который заведомо отрицательный, виден до Generation.

## Requirements

### Functional requirements

1. Форма отклика открывается до Generation, если включён `prefilter.enabled`. Иначе форма открывается как раньше,
   после письма, и анкета только откладывает вакансию.
2. Вопросы читаются из DOM открытой формы или экрана теста: `radio`, `checkbox`, `select`, `textarea`. Известны
   формулировка, варианты ответа и признак обязательности. Поля письма и выбора резюме вопросами не считаются.
3. Вопрос сопоставляется с профилем по кластерам `prefilter.answers`: образование, страна, стаж, зарплата, переезд,
   формат работы, право на работу, срок выхода, языки, электронная трудовая, командировки, достижения. Отдельно
   распознаётся вопрос про технологию: она отвечает «Да», если упомянута в `prefilter.answers.skills`.
4. Ответ строится по вариантам самой анкеты. Подписи приводятся к общим токенам, поэтому «Да», «Есть» и «Имею»
   у разных работодателей означают одно и то же.
5. Вопросы, на которые профиль не ответил, уходят в тот же Generation-вызов, что и письмо: один запрос отдаёт
   письмо и ответы на вопросы. Промпт получает пронумерованный список вопросов, ответ приходит в поле `answers`.
6. Ответ модели принимается только если он совпадает с вариантом анкеты или это текст для текстового вопроса.
   Модель не переопределяет профиль: ответ из `prefilter.answers` важнее.
7. Вердикты профильного разбора. `reject` — ответ гарантированно ведёт к отказу, вакансия отсеивается (`skipped`)
   до Generation. `auto_fill` — все ответы вычислены. `manual_required` — остались вопросы для модели.
8. Отсев ставится только на жёстких требованиях: страна из профиля, право на работу, требуемый стаж и образование.
   Остальные кластеры заполняются честным ответом и вакансию не отсеивают.
9. Правило fail-open: незнакомый вопрос, пустое поле профиля, отсутствие подходящего варианта и «свой вариант»
   отправляют вакансию в ручные и никогда не приводят к отсеву.
10. `prefilter.submit_auto_fill: true` — ответы проставляются в форму, отклик уходит вместе с письмом.
    `false` — ответы вычисляются, вакансия откладывается с причиной `prefilter_auto_fill`.
11. Если проставить удалось не все ответы, форма не отправляется: вакансия уходит в `queued` с причиной
    `questionnaire`, потому что пустой обязательный вопрос всё равно вернёт ошибку.
12. Тест по вакансии проходится тем же путём: «Пройти тест», чтение вопросов, ответы, отправка, чтение результата.
    В тесте отрицательный ответ не отсечка, он лишь снижает балл.
13. Тест пройден — агент сразу отправляет отклик с письмом. Тест не пройден или результат непонятен — вакансия
    в `queued` с причиной «Тест по вакансии не пройден».
14. Ответы на анкету и тест сохраняются в `data.questionary_dir` (`data/questionary`) файлом на вакансию и резюме:
    `{url, profile, channel, title, company, status, saved_at, questionary: [{question, answer}]}`.
15. В записи дневного отчёта появляется блок `questionary: [{question, answer}]` — ответы видны там же, где статус.
16. Префильтр работает только для канала hh.ru: формы отклика с анкетой есть только там.
17. В журнал пишутся событие `prefilter` (вердикт, число вопросов, кластеры, число неизвестных, причина)
    и событие `response_form` при неоткрывшейся форме. Текстов ответов в журнале нет.

### Limitations

- Экран теста поддержан по разметке снимков DOM, проверенного образца теста hh.ru нет: живого прогона не было.
  Многостраничные тесты не поддержаны: тест читается одной страницей.
- Кнопка отправки теста ищется по названиям «Ответить», «Завершить тест», «Отправить ответы», «Далее», «Продолжить»,
  результат — по фразам «Тест пройден» и «Тест не пройден». При смене вёрстки меняется только шаблон в коде.
- После пройденного теста отклик отправляется штатным путём канала. Если hh.ru не вернёт кнопку «Откликнуться»
  (отклик уже создан), вакансия помечается отправленной без нового письма.
- Скриншот формы при уходе в ручные не делается: причина попадает в отчёт, в форму человек заходит сам.
  Выбран JSON-файл ответов: он дешевле скриншота и пригоден для разбора.
- Множественный выбор в чекбоксах не поддержан: проставляется один вариант, иначе вопрос уходит в ручные.
- Ответ про зарплату вписывается только в текстовое поле: в варианты с фиксированными диапазонами агент не угадывает.
- Командировки и электронная трудовая книжка отвечаются только по флагу профиля, без учёта формулировки вопроса.
- Блок `questionary` в отчёте содержит ответы, то есть личные данные: отчёты и файлы ответов лежат в `data` и не
  попадают в git, но при отправке отчёта на email ответы в письмо не включаются.

## Acceptance Criteria

- [x] Анкета разбирается до Generation, письмо не генерируется для вакансий, отсеянных анкетой
- [x] Незнакомые профилю вопросы закрывает один вызов LLM вместе с письмом
- [x] Ответ модели, которого нет среди вариантов анкеты, отбрасывается, вакансия уходит в `queued`
- [x] Отсев по анкете ставит `skipped` с формулировкой вопроса в причине
- [x] `prefilter.submit_auto_fill: true` отправляет отклик с заполненной анкетой, `false` — откладывает
- [x] Частично заполненная анкета не отправляется и уходит в `queued`
- [x] Тест проходится автоматически, после успеха отклик отправляется
- [x] Непройденный тест ставит `queued` с причиной «Тест по вакансии не пройден»
- [x] Ответы сохраняются в `data/questionary` и попадают в блок `questionary` записи отчёта
- [x] `prefilter.enabled: false` сохраняет прежнее поведение: форма открывается после Generation
- [ ] Живой прогон на hh.ru: анкета, тест и отсев анкетой-отсечкой
