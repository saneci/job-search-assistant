# Настройка

Параметры живут в трёх местах, и это разделение осознанное:

| Файл | В git | Что внутри |
|---|---|---|
| `.env` | нет | только секреты: `AITUNNEL_API_KEY`, `SMTP_PASSWORD`, при необходимости `SMTP_USERNAME` |
| `config.yaml` | да | структура и поведение: фильтры и лимиты, LLM, пути, уведомления |
| `config.local.yaml` | нет | личные данные: запросы, стоп-слова и компании, подпись, название резюме, адреса писем |

Приоритет значений: переменные окружения → `config.local.yaml` → `config.yaml` → дефолты схемы.
Секреты в файлах не хранятся: в конфиге есть только имя переменной (`llm.api_key_env`).

## Структура `config.yaml`

Раскладка повторяет схему `agent/config.py` — один формат без legacy-ключей:

| Раздел | Что внутри |
|---|---|
| `search` | `queries`, `area`, `salary_from`, `experience`, `schedule`, `exclude_keywords`, `exclude_companies`, `per_page`, `pages_limit` |
| `pipeline` | `resume`, `limit_per_run`, `delay_between_actions`, `max_vacancies`, `retry` |
| `data` | `logs_retention_days`, `paths` (`profile`, `session_state`, `cache`, `report_dir`, `logs_dir`) |
| `llm` | `api_key_env`, `base_url`, `timeout_seconds`, `system_prompt_path`, `decision`, `generation`, `cover_letter` |
| `browser` | `headless`, `slow_mo_ms`, `channel`, `captcha_wait_seconds` |
| `notifications` | `email`, `report`, `captcha` |

Каждый ключ описан комментарием рядом с ним — отдельного справочника нет, чтобы не держать две
версии правды. Обязательны `search.queries`, `search.area`, `pipeline.limit_per_run` и
`pipeline.delay_between_actions`; остальное имеет дефолты схемы.

Неизвестный ключ (например, старый `limit_per_run` на корне) — ошибка при старте: формат один.

## Регионы

`search.area` принимает числовой id hh.ru или одно из встроенных названий
(`Москва`, `Санкт-Петербург`, `Екатеринбург`, `Новосибирск`, `Казань`, `Россия`).
Для остальных регионов используйте числовой id.

| Код | Город |
|---:|---|
| 1 | Москва |
| 2 | Санкт-Петербург |
| 4 | Новосибирск |
| 3 | Екатеринбург |
| 88 | Казань |
| 2019 | Московская область |
| 2062 | Пушкино (Московская область) |
| 113 | Россия |

Например, для Пушкино (Московская область):

```yaml
search:
  area: 2062
```

`Москва` (1) и `Московская область` (2019) — разные регионы. Пушкино входит
в Московскую область, но на hh.ru у него отдельный id 2062.

Как узнать id другого региона: выберите его в фильтре «Регион» на hh.ru, нажмите
«Сохранить» и посмотрите на параметр `area=` в адресной строке — число и есть id.

## `.env`

Скопируйте `.env.example` в `.env` — переменные описаны в самом файле:

- `AITUNNEL_API_KEY` — ключ LLM-провайдера (без него запуск не начнётся);
- `SMTP_USERNAME`, `SMTP_PASSWORD` — только если нужны письма на email
  ([notifications.md](notifications.md)).

## `config.local.yaml`

Скопируйте `config.local.example.yaml` в `config.local.yaml` и заполните своими данными —
этот файл в `.gitignore`, поэтому личные данные не попадут в репозиторий. Раскладка та же,
что в `config.yaml`; значения перекрывают базу. Что обычно правят:

- `search.queries` — строка или список запросов (поиск идёт по каждому отдельно);
- `search.exclude_keywords` — стоп-слова в названии (отсев без LLM, статус `excluded`),
  `search.exclude_companies` — компании-исключения (тоже `status: excluded`);
- `pipeline.resume.name` — название резюме для подъёма в поиске (пусто — подъём отключён);
- `llm.cover_letter.signature` — подпись с контактами: дописывается кодом через пустую строку
  и считается внутри `llm.cover_letter.max_length`;
- `notifications.email.sender` и `notifications.email.recipient` — адреса писем.

## Проверка конфигурации

Схема описана pydantic-моделями (`agent/config.py`) и проверяется при старте: неизвестный
размер страницы, лишние значения фильтров, отрицательные паузы, порог вне `(0, 1]`, путь за пределы
проекта, несуществующий файл промпта останавливают запуск **до** открытия браузера.
Ошибки собираются за один проход, поэтому в консоли сразу виден весь список с путями из `config.yaml`:

```
Ошибка конфигурации: найдено ошибок: 2
  - pipeline.limit_per_run: Параметр pipeline.limit_per_run должен быть больше нуля
  - notifications.captcha.enabled: должно быть true или false
```

Переопределить значение можно окружением, без правки файлов: вложенные ключи задаются через `__`
(`LLM__DECISION__THRESHOLD=0.9`, `PIPELINE__LIMIT_PER_RUN=10`, `SEARCH__PER_PAGE=50`),
списки — JSON-массивом (`SEARCH__QUERIES='["Java"]'`), секреты читаются по своим именам
(`AITUNNEL_API_KEY`, `SMTP_PASSWORD`). Ключ LLM и SMTP-пароль хранятся как `SecretStr`: они не
печатаются ни в логах, ни в отладочном выводе.

Исключение — личное поле `llm.cover_letter.signature`: из окружения и `.env` оно не читается
вообще, только из `config.local.yaml`/`config.yaml`. Так старый `.env` не может молча перекрыть
файл и испортить многострочную подпись (в `.env` переводы строк превращаются в литеральные `\n`).

## `data/profile.md`

Профиль для LLM (`data.paths.profile`): описание, стек и опыт, подраздел «Примеры» с образцами
писем и раздел «Стиль написания сопроводительных писем». Письмо строится только на фактах
из профиля: чего нет в профиле — не должно попасть в письмо.

## `SYSTEM_PROMPT.md`

Правила оценки, стиля, тона и достоверности, формат JSON-ответа. Единственный источник правил:
правки применяются со следующего запуска, код менять не нужно. Если файл удалить, запуск
остановится с понятной ошибкой.
