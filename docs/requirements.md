# Требования к продукту

1. Агент восстанавливает сессию и, если пора, поднимает резюме в поиске.
2. Ищет вакансии по сохранённым запросам, отбрасывает дубликаты и уже обработанные.
3. Читает описание. Decision LLM решает, подходит ли вакансия профилю.
4. Для подходящих Generation LLM пишет письмо. Код проверяет приветствие, подпись и обязательные ссылки.
5. Агент отправляет отклик, а тесты, анкеты, капчу и недоступные формы откладывает с причиной.
6. После запуска формирует отчёт: консоль, дневной JSON, при необходимости email.

## Статусы фичей

- `INITIATIVE` — идея, работа не начата.
- `IN_PROGRESS` — функция в разработке.
- `DONE` — работает, можно пользоваться. Возможны критические ошибки.
- `SUPPORT` — стабильная версия для всех пользователей.

## Поиск и оценка вакансий

**Цель:** находить подходящие вакансии и не расходовать лимит откликов на неподходящие.

1. Запуск одной командой. При первом запуске пользователь входит в аккаунт вручную, далее сессия
   восстанавливается сама.
2. Резюме поднимается в поиске не чаще заданного интервала.
3. Поиск идёт по сохранённым запросам и фильтрам. Агент проходит всю доступную выдачу или столько
   страниц, сколько разрешено настройкой.
4. Вакансии из прошлых запусков и дубликаты выдачи повторно не обрабатываются.
5. Стоп-слова в названии и компании-исключения отсеиваются без LLM.
6. Агент читает описание вакансии. Decision оценивает соответствие профилю. Отклик возможен только
   при вероятности выше порога.
7. Тесты, анкеты, внешние формы, недоступный отклик и капча автоматически не проходятся: вакансия
   откладывается с понятной причиной.
8. При капче агент ждёт ручного решения и отправляет уведомление. Если решить не удалось, запуск
   останавливается.

**Критерии готовности:** после запуска у каждой вакансии есть статус и причина. Подходящие вакансии либо
отправлены, либо объяснено, почему нет. Лимиты и паузы соблюдены. Повторной обработки нет.

## Письмо и отклик

**Цель:** отправлять корректное письмо, не выдумывая факты о пользователе.

1. Письмо генерируется только для вакансий, которые Decision признал подходящими.
2. Ответ LLM проверяется: невалидный JSON повторяется один раз, затем вакансия получает статус
   ошибки или очередь с причиной.
3. Приветствие и подпись с контактами гарантируются кодом. Если вакансия требует начать письмо
   с конкретного слова, оно остаётся первым.
4. Письмо содержит только факты из профиля: опыт, технологии, проекты и числа не выдумываются.
5. Если вакансия просит ссылки на проекты, письмо обязано их содержать. Ссылки берутся из профиля
   или из настроек. Иначе отклик не отправляется, а причина попадает в отчёт.
6. Пустое письмо и расхождение вердиктов Generation и Decision не приводят к отправке. Решение
   Decision важнее. Вакансия уходит в очередь с содержательной причиной.
7. Причина отказа или откладывания берётся из ответа LLM или сообщения сайта. Общие заглушки
   используются только там, где реальной причины нет.
8. После отправки агент проверяет подтверждение сайта. Если подтверждения нет, отклик не считается
   отправленным, а причина и скриншот сохраняются для разбора.

**Критерии готовности:** ни один отклик не отправлен без обязательного письма или ссылок. У каждой
отложенной вакансии понятная причина. Статусы соответствуют реальным действиям.

## Отчётность

**Цель:** по отчёту понимать результат запуска без чтения логов.

1. В консоли печатается краткий итог: сколько обработано, отправлено, пропущено, отложено, ошибок.
2. Дневной отчёт `data/report/<дата>.json` не удаляется. Одна запись на URL хранится в одном
   экземпляре и при обновлении переносится в отчёт текущей даты. Дата создания записи при этом
   не меняется.
3. Технический журнал `logs/<дата>.jsonl` хранит события и причины. Текст письма, профиль и контакты
   в него не попадают. Срок хранения журналов ограничен.
4. Отчёт и уведомления о капче могут отправляться на email.

Поля дневного отчёта:

| Объект   | Поле                   | Смысл                           | Логика работы                    |
|----------|------------------------|---------------------------------|----------------------------------|
| Отчёт    | `date`                 | дата, за которую собран отчёт   |                                  |
| Отчёт    | `updated_at`           | время последнего обновления     | обновляется при каждом сохранении |
| Отчёт    | `summary`              | количество вакансий по статусам |                                  |
| Вакансия | `vacancies.profile`    | резюме для откликов             | pipeline.resume.name             |
| Вакансия | `vacancies.url`        | ссылка, название, компания      |                                  |
| Вакансия | `vacancies.title`      | ссылка, название, компания      |                                  |
| Вакансия | `vacancies.company`    | ссылка, название, компания      |                                  |
| Вакансия | `vacancies.status`     | текущий статус                  |                                  |
| Вакансия | `vacancies.attempts`   | сколько раз обрабатывали        |                                  |
| Вакансия | `vacancies.created_at` | дата обработки вакансии         | не меняется никогда              |
| Вакансия | `vacancies.updated_at` | время последнего изменения      | обновляется при каждом изменении |
| Вакансия | `vacancies.reason`     | причина статуса                 |                                  |

Статусы вакансии:

| Статус     | Значение                                                        |
|------------|-----------------------------------------------------------------|
| `sent`     | отклик отправлен или уже был отправлен ранее                    |
| `skipped`  | вакансия не подходит, приглашение или нет доступа               |
| `queued`   | нужен ручной отклик: тест, анкета, форма, капча, письмо, ссылки |
| `excluded` | стоп-слово в названии или компания-исключение                   |
| `error`    | сбой обработки                                                  |
| `rejected` | работодатель отказал. Терминальный статус                       |
| `offer`    | оффер. Терминальный статус, только из `sent`                    |

**Критерии готовности:** итоги сходятся с содержимым отчёта. По каждой неотправленной вакансии есть
причина. История не теряется. Персональные данные не попадают в логи.

## Повторная обработка и остановка

1. `--retry` повторяет вакансии со статусами из настроек. `--excluded` — только исключённые.
2. Повтор идёт по ссылкам из отчётов, без поиска и выдачи.
3. При повторе та же запись обновляется: растёт число попыток. Запись переносится в отчёт текущей
   даты, чтобы по URL оставалась одна запись.
4. Лимиты и паузы действуют как в обычном запуске.
5. Ctrl+C — штатная остановка: сессия и отчёт сохраняются, пользователь видит итог без трейсбека.

**Критерии готовности:** повтор не создаёт дубликатов. Число попыток растёт. Остановка не теряет данные.

## Веб-интерфейс и метрики

1. Веб-интерфейс работает с дневными отчётами и не требует браузера hh.ru.
2. В отчёте можно фильтровать вакансии по статусу и искать по названию или компании.
3. Терминальные статусы `rejected` и `offer` нельзя сменить без подтверждения. Из `offer` нельзя
   перейти в другой статус.
4. Страница метрик и API показывают воронку и конверсии за год, квартал, месяц, неделю или день.
5. Одна вакансия учитывается один раз — по последней записи. Период воронки считается по
   `created_at`, а не по файлу, в котором сейчас лежит запись.

Отклики — это `sent`, `rejected` и `offer`. Конверсия в отклик считается от всех вакансий, в оффер —
от откликов.

**Почему по дате создания.** Вакансия остаётся в когорте месяца, когда была обработана.
Если отклик отправлен месяц назад, а ответ пришёл сейчас, вакансия не переезжает в текущий месяц:
меняется только её текущий статус. Это даёт стабильную воронку по когортам. Динамика «сколько
ответов пришло в этом месяце» требует отдельной истории событий и пока не ведётся.

**Критерии готовности:** пользователь находит нужную вакансию и причину. Цифры метрик сходятся
с отчётами. Терминальные статусы защищены от случайного изменения.

## Запуск и управление

Основная команда — `py run.py`, скрипты `run.bat` и `run.sh` готовят окружение и передают аргументы в `run.py`.
Настройки задаются конфигурацией, личные данные хранятся отдельно, секреты — в окружении.

Команды:

| Статус              | Значение                                                      |
|---------------------|---------------------------------------------------------------|
| `--install-browser` | устанавливает браузер                                         |
| `--login`           | ручной вход в аккаунт                                         |
| `--retry`           | повтор по отчётам                                             |
| `--excluded`        | повтор только исключённых вакансий, синоим `--retry excluded` |
| `--notify-test`     | тестовая отправка уведомления на email                        |

## Ограничения

- Работа только через браузер, без API сайта.
- Капча не обходится. Массовая рассылка и работа 24/7 не поддерживаются.
- Персональные данные и сессия хранятся локально. Секреты задаются в окружении.
- Поддерживаемые системы: Windows, macOS, Linux. Python 3.11+.
- Сейчас основной канал поиска — hh.ru. Новые каналы перечислены в перспективах.

## Перспективы

- **Автоматическое прохождение тестов и анкет.** Словарь «вопрос — ответ», точные ответы, при
  отсутствии ответа — очередь и скриншот формы.
- **Новые каналы поиска.** Например, Habr Career. Каналы группируются по резюме.
- **Ассистент чатов.** Распознавание ботов и автоматическое обновление откликов.
- **Анализ зарплат.** Статистика по должностям, медиана и тренды по месяцам.
- **Удобство отчётов.** Сохранение фильтров, понятные цвета статусов, поиск, модальное окно причины,
  ссылка на лог при ошибке.
- **Воронка.** Разрезы по каналам и резюме, проценты на графике, прочерк при отсутствии данных.
- **Управление.** `--serve`, единая справка, вынос CLI в отдельный модуль.
- **Уведомления.** Уведомление в браузере при запущенном сервере, иначе email.
- **Хранение.** SQLite/PostgreSQL и архив старых отчётов.
