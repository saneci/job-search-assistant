# Настройка окружения

Параметры живут в трёх местах, и это разделение осознанное:

| Файл                      | В git | Что внутри                                                                             |
|---------------------------|-------|----------------------------------------------------------------------------------------|
| `.env`                    | нет   | только секреты: `AITUNNEL_API_KEY`, `SMTP_PASSWORD`, при необходимости `SMTP_USERNAME` |
| `../../config.yaml`       | да    | структура и поведение: фильтры и лимиты, LLM, пути, уведомления                        |
| `../../config.local.yaml` | нет   | личные данные: запросы, стоп-слова и компании, подпись, название резюме, адреса писем  |

Приоритет значений: переменные окружения → `../../config.local.yaml` → `config.yaml` → дефолты схемы.
Секреты в файлах не хранятся: в конфиге есть только имя переменной (`llm.api_key_env`).

> [!TIP]
> Возможные проблемы и способы из решений в [troubleshooting.md](../how-to/troubleshooting.md#письма-на-email).

## Структура `.env`

Скопируйте `.env.example` в `.env` — переменные описаны в самом файле:

- `AITUNNEL_API_KEY` — ключ LLM-провайдера (без него запуск не начнётся).
- `SMTP_USERNAME`, `SMTP_PASSWORD` — только если нужны письма на email
  ([notifications.md](../features/notifications/spec.md)).

## Структура `../../config.yaml`

Раскладка повторяет схему `../../agent/config.py` - каждый ключ описан комментарием рядом с ним — отдельного справочника
нет,
чтобы не держать две версии правды. Обязательны `pipeline.limit_per_run` и `pipeline.delay_between_actions`.
Для канала `hh` обязательны `search.queries` и `search.area`, для `habr` они не нужны. Остальное имеет
дефолты схемы. Неизвестный ключ (например, `limit_per_run` на корне) — ошибка при старте приложения.

## Каналы поиска

`search.channel` выбирает сайт: `hh` (по умолчанию, поиск по запросам) или `habr` (лента «Подходящие»
career.habr.com). У каналов раздельные сессии и браузерные профили:

- `data.paths.session_state` — сессия hh.ru (по умолчанию `data/hh-state.json`).
- `data.paths.habr_session_state` — сессия career.habr.com (`../../data/habr-state.json`).
- `data.paths.habr_profile` — постоянный профиль Chrome для Habr (`../../data/browser-profile`): без него
  hCaptcha на входе не отрисовывается.

Ручной вход на сайт выбранного канала: `./run.sh --login`. В отчётах у каждой вакансии есть поле
`channel` (`hh` или `habr`). В веб-интерфейсе отчёт фильтруется по каналу, а метрики показывают
распределение вакансий по каналам.

Канал можно переопределить на один запуск: `./run.sh --channel habr` (псевдоним `--ch`). Опция действует
для обычного запуска, `--retry` и `--login`. Без опции канал берётся из `search.channel`.

Канал `habr` не использует `search.queries`, `search.area`, `search.experience`, `search.schedule`,
`search.salary_from` и `search.per_page`: лента строится по профилю пользователя и отдаёт по 25 карточек.
`search.pages_limit` работает и там: ограничивает число страниц ленты.

## Структура `../../config.local.yaml`

Скопируйте `../../config.local.example.yaml` в `config.local.yaml` и заполните своими данными —
этот файл в `.gitignore`, поэтому личные данные не попадут в репозиторий. Раскладка та же,
что в `config.yaml`. Значения перекрывают базу. Что обычно правят:

- `search.queries` — строка или список запросов (поиск идёт по каждому отдельно, только для канала `hh`).
- `search.exclude_keywords` — стоп-слова в названии (отсев без LLM, статус `excluded`),
  `search.exclude_companies` — компании-исключения (тоже `status: excluded`).
- `pipeline.resume.name` — название резюме для подъёма в поиске (пусто — подъём отключён).
- `llm.cover_letter.signature` — подпись с контактами: дописывается кодом через пустую строку
  и считается внутри `llm.cover_letter.max_length`.
- `llm.cover_letter.pet-projects` — ссылки на проекты: Generation использует их, если вакансия
  просит приложить ссылку в письме. Без ссылки отклик не отправляется, причина попадает в отчёт.

- `notifications.email.sender` и `notifications.email.recipient` — адреса писем.

## Регионы поиска на hh.ru

`search.area` принимает числовой id hh.ru или одно из встроенных названий (`Москва`, `Санкт-Петербург`, `Екатеринбург`,
`Новосибирск`, `Казань`, `Россия`). Для остальных регионов используйте числовой id.

|  Код | Город                        |
|-----:|------------------------------|
|    1 | Москва                       |
|    2 | Санкт-Петербург              |
|    4 | Новосибирск                  |
|    3 | Екатеринбург                 |
|   88 | Казань                       |
| 2019 | Московская область           |
| 2062 | Пушкино (Московская область) |
|  113 | Россия                       |

Например, для Пушкино (Московская область):

```yaml
search:
  area: 2062
```

`Москва` (1) и `Московская область` (2019) — разные регионы. Пушкино входит в Московскую область, но на hh.ru у него
отдельный id 2062.

Как узнать id другого региона: выберите его в фильтре «Регион» на hh.ru, нажмите «Сохранить» и посмотрите на параметр
`area=` в адресной строке — число и есть id.

## `../../data/profile.md`

Профиль для LLM (`data.paths.profile`): описание, стек и опыт, подраздел «Примеры» с образцами писем и раздел «Стиль
написания сопроводительных писем». Письмо строится только на фактах из профиля: чего нет в профиле — не должно попасть в
письмо.

## `../../SYSTEM_PROMPT.md`

Правила оценки, стиля, тона и достоверности, формат JSON-ответа. Единственный источник правил: правки применяются со
следующего запуска, код менять не нужно. Если файл удалить, запуск остановится с понятной ошибкой.
