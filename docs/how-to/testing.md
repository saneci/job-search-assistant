# Тесты и проверки

Единая точка входа для проверок проекта. Правила, что и как тестировать, описаны здесь, а
[AGENTS](../../AGENTS.md) и [README](../../README.md) ссылаются сюда вместо повторения команд.

## Подготовка

```bash
./.venv/Scripts/python.exe -m pip install -r requirements-dev.txt   # Windows
# .venv/bin/python -m pip install -r requirements-dev.txt           # macOS/Linux
```

`requirements-dev.txt` подключает рабочие зависимости (`requirements.txt`, `requirements-web.txt`),
`pytest` и `pyflakes`. Для JS-тестов нужен `node` в `PATH` (версия 18 или новее с встроенным `node:test`).

## Перед завершением задачи

```bash
./.venv/Scripts/python.exe -m pytest -q
./.venv/Scripts/python.exe -m pyflakes agent run.py tests web
```

Обе команды должны проходить без замечаний: упавший тест — это регрессия, а не повод поправить
ожидание, а предупреждение `pyflakes` — неиспользуемый импорт или переменная.

## Что проверяется чем

| Инструмент                    | Что покрывает                                                     |
|-------------------------------|-------------------------------------------------------------------|
| `pytest`                      | логика агента, конфиг, отчёты, веб-роуты и рендер шаблонов        |
| `pyflakes`                    | неиспользуемые импорты и переменные в `agent`, `run.py`, `tests`, `web` |
| `node --test tests/js/*.mjs`  | чистая логика фильтров отчёта и вёрстка графиков метрик           |

JS-тесты запускаются напрямую и через `pytest`: обёртки `tests/test_filters_js.py` и
`tests/test_charts_js.py` вызывают `node --test`. Если Node не установлен, `pytest` помечает эти
проверки как пропущенные, остальной набор выполняется полностью.

```bash
node --test tests/js/filters.test.mjs   # фильтры отчёта: адрес, хранилище, счётчики
node --test tests/js/charts.test.mjs    # графики метрик: разметка, пороги, легенды
```

Браузер в тестах не запускается: страницы метрик и отчёта проверяются по HTML, CSS и JS-функциям,
сеть подменяется через `httpx.MockTransport`.

## Правила написания тестов

- Новая логика — новый тест. Тест на исправление бага добавляется вместе с исправлением.
- Существующие тесты не меняются: если тест упал, исправляется код.
- Тесты конфига оформляются таблицами `parametrize`: дефолты, ошибки, приоритет источников.
- Тесты браузерных сценариев не пишутся, вместо них — чистые функции и проверки разметки.
- Данные пользователя в тестах не используются: только сгенерированные заглушки.

## Проверка интерфейса вручную

Автотесты не видят вёрстку глазами, поэтому после правок веб-интерфейса откройте страницы и
убедитесь, что разметка не разъезжается:

```bash
./.venv/Scripts/uvicorn.exe web.main:app --reload
```

- `/` — главная: ссылки на отчёт и метрики, переключение темы
- `/report` — фильтры стоят одной строкой, меню не сдвигает панель, таблица без наложения текста
- `/metrics` — период, фильтр резюме, графики и легенды

Временные скрипты и скриншоты складывайте в `.tmp/` и удаляйте после проверки: каталог не в git.
