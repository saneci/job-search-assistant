# Соглашения об оформлении справки CLI

## Зачем это нужно

Единый формат обозначения аргументов в справке CLI:

- снижает когнитивную нагрузку на пользователя;
- позволяет AI-агенту однозначно генерировать и парсить справку;
- совпадает с соглашениями POSIX/GNU и `argparse`/`click`/`clap`, поэтому не приходится объяснять каждому инструменту
  «свой» синтаксис.

## Базовые обозначения

| Нотация     | Значение                                                   | Пример                   |
|-------------|------------------------------------------------------------|--------------------------|
| `ARG`       | обязательный позиционный/именованный аргумент (без скобок) | `--config FILE`          |
| `<ARG>`     | плейсхолдер «подставь значение» (угловые скобки)           | `--config <FILE>`        |
| `[ARG]`     | **необязательный** аргумент (квадратные скобки)            | `--retry [STATUS]`       |
| `[ARG...]`  | необязательный, может повторяться                          | `--exclude [PATTERN...]` |
| `ARG...`    | обязательный, может повторяться                            | `FILES...`               |
| `--foo, -f` | короткая и длинная форма одной опции                       | `--retry`, `-r`          |
| `(a\|b)`    | взаимоисключающий выбор                                    | `--format (json\|yaml)`  |

### Правила:

1. **Квадратные скобки = необязательность.** Никогда не используйте `[ ]` как часть имени опции.
2. **Угловые скобки = плейсхолдер.** `<FILE>`, `<STATUS>`, `<N>` — понятнее, чем абстрактный `ARG`.
3. **Имена опций — как в коде.** Если опция называется `--install-browser`, пишите `--install-browser`,
   а не `--[INSTALL BROWSER]`.
4. **Один плейсхолдер — одно слово в верхнем регистре.** `FILE`, `STATUS`, `PATH`, `N`.
5. **Значения по умолчанию** — в описании: `(по умолчанию: config.yaml)`.

## Исправленный пример

### Было:

```
--config CONFIG         путь к YAML-конфигурации, по умолчанию: config.yaml в корне проекта
--[NOTIFY TEST]         отправить тестовое письмо-уведомление и выйти
--retry, --re [СТАТУС]  повторить обработку вакансий, без поиска
```

### Стало:

```
--config <FILE>          путь к YAML-конфигурации, по умолчанию: config.yaml в корне проекта
--notify-test            отправить тестовое письмо-уведомление и выйти
--retry, --re [STATUS]   повторить обработку вакансий, без поиска
```

### Что изменилось:

- `CONFIG` → `<FILE>` — плейсхолдер описывает тип значения;
- `--[NOTIFY TEST]` → `--notify-test` — квадратные скобки убраны, пробел заменён на дефис (стандарт GNU);
- `[СТАТУС]` → `[STATUS]` — латиница для совместимости с терминалами и парсерами;
- выравнивание описаний по одной колонке (2+ пробела после самой длинной опции).

## Чек-лист для самопроверки

Перед генерацией/правкой справки CLI проверь:

- [ ] обязательные аргументы — без скобок
- [ ] необязательные — в `[ ]`
- [ ] плейсхолдеры — в `< >`, ВЕРХНИЙ РЕГИСТР, латиница
- [ ] имена опций совпадают с тем, что реально парсит код (`argparse`/`click`/`clap`)
- [ ] нет квадратных скобок внутри имён опций
- [ ] нет пробелов внутри имён опций (`--notify-test`, а не `--notify test`)
- [ ] дефолты указаны в описании, а не в сигнатуре
- [ ] короткая и длинная формы — через запятую: `-r, --retry`
- [ ] описания выровнены по одной колонке
- [ ] примеры вызова добавлены в конец `--help` (секция `Examples:`)
