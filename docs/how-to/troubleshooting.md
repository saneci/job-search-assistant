# Возможные проблемы и их решения

## Запуск и браузер

**Chrome обновился, и браузер перестал запускаться.** Playwright управляет установленным Chrome через
CDP, и очень крупные обновления Chrome иногда опережают установленную версию Playwright. Лечится без
правок кода:


```bash
.venv\Scripts\python.exe -m pip install -U playwright    # Windows
# .venv/bin/python -m pip install -U playwright          # macOS/Linux
```

Если не помогло — временно переключитесь на Chromium: `browser.channel: ""` и `run.bat --install-browser`.

**Кажется, что скрипт «завис».** Долгие паузы ожидаемы: загрузка страницы hh.ru ждётся до 45 секунд,
ожидание карточек выдачи — до 15 секунд, плюс случайные паузы `pipeline.delay_between_actions`. Прогресс
печатается в консоль и пишется в `data/logs/<дата>.jsonl`. Если страница не загрузилась, в консоли будет
«Не удалось открыть поиск…», ошибка попадёт в отчёт, а для вакансии сохранится скриншот
`data/logs/<run_id>-error-N.png`.

**Закрыли окно браузера во время работы.** Запуск останавливается с понятным сообщением, отчёт
сохраняется. Запустите снова — уже отработанные вакансии не попадут в отчёт второй раз.

**Каждый запуск требует входа заново.** Удалите файл сессии канала (`data/hh-state.json` или
`../../data/habr-state.json`) и выполните `run.bat --login`: убедитесь, что вход завершён до нажатия Enter.
Сессия живёт, пока сайт её не сбросит; после сброса вход повторяется тем же способом.

**`data/hh-state.json` больше мегабайта.** Так hh.ru хранит в localStorage кэш шрифтов (`magritteFontsNewFont`,
`xhhFontsFont`, `chatikFontsFont`) — около 1 МБ. При сохранении сессии
приложение выбрасывает эти записи: для входа они не нужны, браузер скачает шрифты заново.
Файл перезаписывается при каждом запуске, так что расти бесконечно он не может.

## Капча и отклики

**hh.ru показал капчу.** Приложение её не обходит: печатает в консоль просьбу ввести текст с картинки,
сохраняет скриншот `data/logs/<run_id>-captcha.png` и ждёт до `browser.captcha_wait_seconds` секунд.
Введите текст и нажмите «Отправить» — отклик продолжится с той же вакансии. Если не успели (или включён
`browser.headless: true`), вакансия помечается отложенной, запуск останавливается. Дальше — подождите
10–15 минут, уменьшите `pipeline.limit_per_run` и увеличьте паузы `pipeline.delay_between_actions`.

**Career Habr показал hCaptcha.** Капча не обходится: приложение ждёт `browser.captcha_wait_seconds`
и отправляет одно письмо. hCaptcha рисуется только в постоянном профиле (`data.paths.habr_profile`),
поэтому вход выполняйте через `./run.sh --login` и решайте капчу вручную в открытом окне.

**Браузер предупреждает про `--no-sandbox`.** Опцию добавляет Playwright: по умолчанию sandbox Chromium
выключен. Настройка `browser.chromium_sandbox: true` (значение по умолчанию) включает его, и предупреждение
исчезает. Если Chromium не стартует — запуск от root или Linux без user namespaces — поставьте `false`.

**Вакансия с тестом/анкетой, а в консоли «отклик отправлен».** Отправка подтверждается явным признаком
на странице («Отклик отправлен» и т.п.). Если после нажатия «Откликнуться» появился экран теста,
анкеты или внешней формы — вакансия помечается `queued` с причиной про тестирование (или анкету/сайт
работодателя), а запуск продолжается со следующей. Если подтверждения нет — причина «hh.ru не подтвердил
отправку отклика — проверьте вакансию вручную», подробности — в событии `respond_state` и скриншоте
`data/logs/<run_id>-respond-unknown.png`.

**Сколько откликов уже отправлено.** Лимит `pipeline.limit_per_run` считает именно отправленные отклики:
отложенные лимит не расходуют. В строке отправки виден счётчик: «отклик отправлен (всего N из M)».

**Резюме не поднимается.** Заполните `pipeline.resume.name` — полное название резюме из списка резюме hh.ru.
Отметка о подъёме лежит в `data/cache.json`: если резюме поднимали меньше `pipeline.resume.boost_interval_hours`
назад, приложение пишет об этом в лог и идёт дальше. Если кнопки «Поднять в поиске» нет (hh сам поднял
резюме) — подъём пропускается и кэш не обновляется.

## Поиск и отчёт

**Вакансий не найдено.** Проверьте `search.area`, `search.experience`, `search.schedule` (значения hh.ru:
`between1And3`, `remote`, …) и сам запрос. При необходимости задайте `search.pages_limit` вручную. URL с фильтрами виден
в логе — можно открыть глазами.

**На сайте вакансий больше, чем в отчёте.** «Обработано вакансий» считает все карточки, которые мы
прошли, включая уже обработанные в прошлых запусках (`../../data/report`). Глубина по умолчанию считается
сама: `ceil(найдено / search.per_page)`, то есть на всю выдачу запроса — в логе видна строка плана
«По запросу «Java developer» найдено 545 вакансий, разделяю обработку на 6 страниц». Явный `search.pages_limit`
ограничивает глубину, предохранитель — не больше 50 страниц на запрос. Дальше по каждой странице
печатается «Обработка 100 вакансий из результата запроса «Java developer»: страница 1 из 6».

**В логе «найдено 20 вакансий», хотя `search.per_page: 100`.** hh.ru рисует карточки по мере прокрутки:
сначала в DOM только 20, остальные подгружаются при скролле. Приложение прокручивает страницу само (`_load_all_cards`) и
ждёт, пока карточек не станет столько, сколько заказали. Если сеть медленная,
очередной запуск просто доберёт остаток — уже пройденные вакансии не обрабатываются повторно.

**В отчёте «Вас пригласили на эту вакансию» или «У вас нет доступа к этой вакансии».** Это статус
`skipped`: на странице нет формы отклика, откликаться незачем. Вакансия считается пройденной и
повторно не обрабатывается, пока её запись есть в файле дня. Файлы дня не удаляются — история
хранится всё время, чистим только журналы в `data/logs` (старше `data.logs_retention_days`).

**Работодатель ответил отказом — где это видно?** На странице вакансии появляется отметка
«Вам отказали»: агент пишет такую вакансию со статусом `rejected` и причиной «По отклику пришёл
отказ». Отметить отказ вручную можно в веб-интерфейсе: выбор статуса «Отказ» обновляет только
статус, причину и время, попытки отклика не пересчитываются.

**Пришёл оффер.** Выберите в веб-интерфейсе статус «Оффер» — он попадёт в воронку как оффер
и изменит конверсию в оффер. Агент сам этот статус не ставит: оффер подтверждает человек.

**«Отправлено» с причиной «отклик уже отправлен».** Так помечаются вакансии, где hh.ru показывает
уже отправленный отклик (например, вы откликнулись руками или это было в прошлом запуске). В файле
дня у них статус `sent`, в вебе они в «Отправлено», а не в «Не подходит». Лимит `pipeline.limit_per_run` такие
вакансии не расходуют, повторно они не обрабатываются.

**Запуск идёт ночью — почему появился второй файл?** Журнал и дневной отчёт — файлы даты: после
полуночи приложение открывает `data/logs/<новая дата>.jsonl` и `data/report/<новая дата>.json`, в логе
одна строка «Наступила новая дата…» (событие `new_day`).

**«Не удалось разобрать config.yaml».** Ошибка YAML-синтаксиса: проверьте отступы и кавычки.
JSON тоже принимается, так как это подмножество YAML. `run.bat --help` конфиг не читает,
`run.bat --install-browser` — читает и покажет ошибку.

**Кракозябры в консоли.** `run.bat` и `../../run.sh` сами включают UTF-8 (в `run.sh` `chcp` вызывается
по полному пути `C:/Windows/System32/chcp.com`). При ручном запуске через `./run.sh` кодировку
терминала нужно выставить самому.

## LLM

**HTTP 401** — неверный `AITUNNEL_API_KEY`. **HTTP 402** — закончился баланс AITUNNEL. **HTTP 429/5xx** — временные
лимиты, приложение делает пару повторов и продолжает работу.
Ответ не в формате JSON повторяется один раз, затем вакансия попадает в отчёт со статусом `error`.

## Письма на email

**Письмо о капче не пришло.** Нужен настроенный SMTP-канал (`notifications.email.enabled: true`
и `SMTP_PASSWORD` в `.env`) и включённый вид писем `notifications.captcha.enabled: true`. Проверьте
канал командой `run.bat --notify-test`. В JSONL будет событие `email_notify` с `sent: false` и причиной.
Сбой отправки запуск не останавливает: капча всё равно ждёт решения в окне браузера.

**Отчёт не пришёл на email.** Нужны `notifications.email.enabled: true` и
`notifications.report.enabled: true`, заполненные `smtp_host`, `smtp_port`, `use_ssl` в `../../config.yaml`,
`sender` и `recipient` в `config.local.yaml`, `SMTP_PASSWORD` в `.env`. Если отправка выключена
или не настроена, отчёт печатается в консоль и сохраняется в `data/report/<дата>.json` — данные
не теряются.

**«SMTP-сервер закрыл соединение».** Провайдер блокирует SMTP-вход: смените `smtp_host`/`sender` —
подробности в [notifications.md](../features/notifications/spec.md#если-smtp-блокирует-вход).

## Ручная установка

Если скрипты не подходят, установите окружение вручную.

```bash
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt   # Windows
# python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # macOS/Linux
```

Браузер:

- по умолчанию `browser.channel: chrome` — используется установленный Google Chrome, скачивать
  ничего не нужно.
- если Chrome нет: поставьте `browser.channel: ""` и выполните `run.bat --install-browser`
  (или `.venv\Scripts\python.exe -m playwright install chromium`).

Проверка окружения: `run.bat --help` не читает конфиг, а `run.bat --install-browser` читает — покажет
ошибки конфигурации без запуска браузера и LLM.
