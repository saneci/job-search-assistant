# Логи и отчёты

## Консоль

Строки по вакансиям: `[дата время] [id] Название — Компания: событие`.

```
[2026-10-22 11:15:26] [136966625] Java-разработчик — АО ГНИВЦ: открываю вакансию
[2026-10-22 11:17:06] [136966625] Java-разработчик — АО ГНИВЦ: LLM-решение: «подходит» (порог 0.80, подходит=0.99, не подходит=0.01)
[2026-10-22 11:17:34] [136966625] Java-разработчик — АО ГНИВЦ: LLM-вердикт: Ключевые требования совпадают с опытом...
[2026-10-22 11:17:38] [136966625] Java-разработчик — АО ГНИВЦ: отклик отправлен (всего 2 из 20)
```

`id` в квадратных скобках — номер вакансии hh.ru: по нему видно, дубликат это или разные вакансии
с одинаковым названием. Метка времени локальная; в JSONL время в поле `ts`, номер — в `vacancy_id`.

`LLM-решение` — вердикт приложения: `подходит`, если `P("подходит")` выше `llm.decision.threshold`,
иначе `не подходит` (даже когда у модели вариант «подходит» набрал больше голосов, например 0.57
против 0.43). Сырой выбор модели по максимальной вероятности — в поле `model_choice`, вердикт
приложения — в `llm_verdict`.

Одна и та же вакансия не обрабатывается дважды: дубликаты в выдаче (по id и по паре «название + компания»)
отбрасываются со строкой «дубликат в выдаче, пропускаю», вакансии из прошлых запусков — «уже обрабатывалась
<дата>, пропускаю».

## Дневной отчёт `data/report/<дата>.json`

Шапка с итогами и плоский список вакансий:

```json
{
  "date": "2026-10-22",
  "updated_at": "2026-10-22T16:09:02+03:00",
  "summary": {"sent": 1, "skipped": 1, "queued": 1, "excluded": 1, "error": 0, "rejected": 0, "offer": 0},
  "vacancies": [
    {
      "url": "https://hh.ru/vacancy/138144810",
      "title": "Java junior разработчик интеграционных решений",
      "company": "Банк Русский Стандарт",
      "status": "skipped",
      "reason": "вероятность 0.57 не выше порога 0.80",
      "attempts": 1,
      "processed_at": "2026-10-22T16:02:12+03:00"
    }
  ]
}
```

Статусы:

- `sent` — отклик отправлен (в том числе «отклик уже отправлен», если hh.ru его принял раньше: причина это
  поясняет, лимит запуска такая вакансия не расходует);
- `skipped` — не подошло по мнению LLM, «Вас пригласили», «У вас нет доступа к этой вакансии»;
- `queued` — нужен ручной отклик (тест, анкета, внешняя форма, капча, пустое письмо);
- `excluded` — стоп-слово в названии (`search.exclude_keywords`) или компания из `search.exclude_companies`;
- `error` — сбой обработки, причина в `reason`;
- `rejected` — работодатель отказал по отклику («Вам отказали» на странице), причина «По отклику пришёл отказ»;
- `offer` — ручной статус в веб-интерфейсе: по отклику пришёл оффер.

`rejected` и `offer` — терминальные статусы: после их сохранения вакансию нельзя перевести в другой
статус. `offer` разрешён только из `sent`: если отклик ещё не отправлен, сервер вернёт `409`.
В веб-интерфейсе селект терминального статуса заблокирован, а перед фиксацией показывается
предупреждение о необратимости.

`attempts` — сколько раз вакансию обрабатывали (растёт при `--retry`), `processed_at` — время
последней обработки. Отдельного файла очереди нет: отложенные — это `queued` в том же файле.

## Веб-метрики

Страница `/metrics` считает по всем файлам `data/report`, а фильтр периода оставляет вакансии
с `processed_at` внутри календарного года, квартала, месяца, недели или дня. Точка отсчёта —
самая свежая дата в данных, поэтому старые отчёты не дают пустую воронку. API
`/api/v1/metrics` принимает `period`; без него считаются все отчёты.

- одна вакансия — одна запись: при повторах берётся самая свежая по `processed_at`;
- отклики: `responses = sent + rejected + offer` (статусы в JSON считаются как есть);
- конверсия в отклик: `responses / все уникальные вакансии`;
- конверсия в оффер: `offer / responses`;
- доля отказов: `rejected / responses`;
- игнор: `sent / responses` — отклики, по которым ещё нет ответа;
- `skipped`, `excluded`, `queued`, `error` — остальные обработанные вакансии.

Слово «Отклики» означает только общее число `responses`. Статус `sent` и на воронке, и в отчёте
подписан «Отправлено»: это отклики без ответа. Поэтому в легенде распределения «Отправлено (46)»
и «Отказы (4)» — части одного целого «Отклики (50)».

Дата в шапке воронки печатается в том же виде, что колонка «Дата» отчёта: `yyyy-mm-dd hh:mm:ss`.

`offer` агент сам не ставит: его выбирает человек в таблице отчёта, как и `rejected`.

Файлы дня **не удаляются никогда** — это история вакансий (пригодится для аналитики). Срок хранения
есть только у логов: файлы `logs/` старше `data.logs_retention_days` удаляются при старте.
Формат один: файл другого вида (например, старый массив записей) не читается — такие вакансии
проходятся заново.

Причины `queued`: «Для отклика на вакансию необходимо пройти тестирование», «…необходимо заполнить
анкету», «Отклик нужно отправить на сайте работодателя», «Нужно заполнить сопроводительное письмо
вручную», «hh.ru просит пройти капчу: откликнитесь вручную», «hh.ru не подтвердил отправку отклика —
проверьте вакансию вручную». Код причины — в JSONL (поле `code`).

Повторная обработка по этим записям — [usage.md](usage.md#как-работает---retry).

## JSONL `logs/<дата>.jsonl`

Один файл на дату, перезапуски дописывают в конец; `run_id` в каждой записи отделяет запуски.
В событии — имя события, `vacancy` (без номера), `vacancy_id`, `llm_reason` и детали: URL, вероятности,
`letter_length`. Текст письма, профиль и контакты в логи не пишутся — только факты и длины.

`llm_reason` пишется и для одобрений, и для отказов (для отказов — из вероятностей, либо текст модели
при `llm.decision.explain_rejections: true`); `llm_reason_source` показывает, откуда причина: `model`
или `threshold`.

Когда hh.ru не подтвердил отклик (`status: unknown`), пишется событие `respond_state`: `page_url`,
текст формы отклика (`form_text`, без письма) и `letter_length`, плюс скриншот
`logs/<run_id>-respond-unknown.png` (если снять не удалось — событие `screenshot_error`).

Отдельного файла деталей запуска нет: итоги — в консоли и письме, по вакансиям — в дневном отчёте,
события — в JSONL.

## Отчёт в конце запуска

```
=================================
Отчёт за 2026-10-21 15:19
=================================
- Обработано вакансий: 12
- Отправлено откликов: 1
- Пропущено (не подошло): 7
- Исключённые вакансии: 1
- Отказы по откликам: 2
- Отложено (тесты/анкеты): 0
- Ошибок при обработке: 1
- Причина остановки: достигнут лимит откликов за запуск (1)
- Длительность: 5 мин 31 с
```

Строки «Исключённые вакансии», «Отказы по откликам» и «Ошибок при обработке» появляются, только
если такие вакансии были.
Списка отправленных в отчёте нет — он в дневном файле, путь печатается ниже (в консоли — отдельной
строкой с меткой времени, в письме — в конце отчёта).

## Файлы

Всё, что приложение создаёт и изменяет, лежит в `data/` (каталог не попадает в git), логи — в `logs/`.
Пути настраиваются секцией `paths` в `config.yaml`.

| Файл | Назначение |
| --- | --- |
| `data/profile.md` | профиль пользователя для LLM (`data.paths.profile`) |
| `data/state.json` | cookies + localStorage hh.ru (`data.paths.session_state`) |
| `data/cache.json` | когда последний раз поднимали резюме в поиске (`data.paths.cache`) |
| `data/report/*.json` | дневной отчёт: шапка с итогами и вакансии со статусами (`data.paths.report_dir`); вакансии с уже отправленным откликом лежат со статусом `sent` и причиной «отклик уже отправлен» |
| `logs/<дата>.jsonl` | события за дату (JSON Lines), включая решения LLM (`data.paths.logs_dir`) |
| `logs/<run_id>-*.png` | скриншоты проблемных состояний: капча, ошибка, неизвестный ответ |
