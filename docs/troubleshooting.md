# Возможные проблемы и их решения

## Запуск и браузер

**Chrome обновился, и браузер перестал запускаться.** Playwright управляет установленным Chrome через
CDP, и очень крупные обновления Chrome иногда опережают установленную версию Playwright. Лечится без
правок кода:

```bash
.venv\Scripts\python.exe -m pip install -U playwright    # Windows
# .venv/bin/python -m pip install -U playwright          # macOS/Linux
```

Если не помогло — временно переключитесь на Chromium: `browser.channel: ""` и `run.bat --install-browser`.

**Кажется, что скрипт «завис».** Долгие паузы ожидаемы: загрузка страницы hh.ru ждётся до 45 секунд,
ожидание карточек выдачи — до 15 секунд, плюс случайные паузы `delay_between_actions`. Прогресс
печатается в консоль и пишется в `logs/<дата>.jsonl`. Если страница не загрузилась, в консоли будет
«Не удалось открыть поиск…», ошибка попадёт в отчёт, а для вакансии сохранится скриншот
`logs/<run_id>-error-N.png`.

**Закрыли окно браузера во время работы.** Запуск останавливается с понятным сообщением, отчёт
сохраняется. Запустите снова — уже отработанные вакансии не попадут в отчёт второй раз.

**Каждый запуск требует входа заново.** Удалите `data/state.json` и выполните `run.bat --login`:
убедитесь, что вход в hh.ru завершён до нажатия Enter. Сессия живёт, пока hh.ru её не сбросит;
после сброса вход повторяется тем же способом.

**`data/state.json` больше мегабайта.** Так hh.ru хранит в localStorage кэш шрифтов
(`magritteFontsNewFont`, `xhhFontsFont`, `chatikFontsFont`) — около 1 МБ. При сохранении сессии
приложение выбрасывает эти записи: для входа они не нужны, браузер скачает шрифты заново.
Файл перезаписывается при каждом запуске, так что расти бесконечно он не может.

## Капча и отклики

**hh.ru показал капчу.** Приложение её не обходит: печатает в консоль просьбу ввести текст с картинки,
сохраняет скриншот `logs/<run_id>-captcha.png` и ждёт до `browser.captcha_wait_seconds` секунд.
Введите текст и нажмите «Отправить» — отклик продолжится с той же вакансии. Если не успели (или включён
`headless: true`), вакансия помечается отложенной, запуск останавливается. Дальше — подождите
10–15 минут, уменьшите `limit_per_run` и увеличьте паузы `delay_between_actions`.

**Вакансия с тестом/анкетой, а в консоли «отклик отправлен».** Отправка подтверждается явным признаком
на странице («Отклик отправлен» и т.п.). Если после нажатия «Откликнуться» появился экран теста,
анкеты или внешней формы — вакансия помечается `queued` с причиной про тестирование (или анкету/сайт
работодателя), а запуск продолжается со следующей. Если подтверждения нет — причина «hh.ru не подтвердил
отправку отклика — проверьте вакансию вручную», подробности — в событии `respond_state` и скриншоте
`logs/<run_id>-respond-unknown.png`.

**Сколько откликов уже отправлено.** Лимит `limit_per_run` считает именно отправленные отклики:
отложенные лимит не расходуют. В строке отправки виден счётчик: «отклик отправлен (всего N из M)».

**Резюме не поднимается.** Заполните `resume.name` — полное название резюме из списка резюме hh.ru.
Отметка о подъёме лежит в `data/cache.json`: если резюме поднимали меньше `resume.boost_interval_hours`
назад, приложение пишет об этом в лог и идёт дальше. Если кнопки «Поднять в поиске» нет (hh сам поднял
резюме) — подъём пропускается и кэш не обновляется.

## Поиск и отчёт

**Вакансий не найдено.** Проверьте `area`, `experience`, `schedule` (значения hh.ru: `between1And3`,
`remote`, …) и сам запрос; при необходимости задайте `pages_limit` вручную. URL с фильтрами виден
в логе — можно открыть глазами.

**На сайте вакансий больше, чем в отчёте.** «Обработано вакансий» считает все карточки, которые мы
прошли, включая уже обработанные в прошлых запусках (`data/report`). Глубина по умолчанию считается
сама: `ceil(найдено / per_page)`, то есть на всю выдачу запроса — в логе видна строка плана
«Запрос «Java developer» на hh.ru нашёл 545 вакансий: 6 страниц по 100». Явный `pages_limit`
ограничивает глубину, предохранитель — не больше 50 страниц на запрос. Дальше по каждой странице
печатается «Обработка результатов запроса «Java developer»: 100 вакансий на странице 1».

**В логе «найдено 20 вакансий», хотя `per_page: 100`.** hh.ru рисует карточки по мере прокрутки:
сначала в DOM только 20, остальные подгружаются при скролле. Приложение прокручивает страницу само
(`_load_all_cards`) и ждёт, пока карточек не станет столько, сколько заказали; если сеть медленная,
очередной запуск просто доберёт остаток — уже пройденные вакансии не обрабатываются повторно.

**«Не удалось разобрать config.yaml».** Ошибка YAML-синтаксиса: проверьте отступы и кавычки.
JSON тоже принимается, так как это подмножество YAML. `run.bat --help` конфиг не читает,
`run.bat --install-browser` — читает и покажет ошибку.

**Кракозябры в консоли.** `run.bat` и `run.sh` сами включают UTF-8 (в `run.sh` `chcp` вызывается
по полному пути `C:/Windows/System32/chcp.com`). При ручном запуске через `py run.py` кодировку
терминала нужно выставить самому.

## LLM

**HTTP 401** — неверный `AITUNNEL_API_KEY`; **HTTP 402** — закончился баланс AITUNNEL;
**HTTP 429/5xx** — временные лимиты, приложение делает пару повторов и продолжает работу.
Ответ не в формате JSON повторяется один раз, затем вакансия попадает в отчёт со статусом `error`.

## Письма на email

**Письмо о капче не пришло.** Нужен настроенный SMTP-канал (`notifications.email.enabled: true`
и `SMTP_PASSWORD` в `.env`) и включённый вид писем `notifications.captcha.enabled: true`. Проверьте
канал командой `run.bat --notify-test`; в JSONL будет событие `email_notify` с `sent: false` и причиной.
Сбой отправки запуск не останавливает: капча всё равно ждёт решения в окне браузера.

**Отчёт не пришёл на email.** Нужны `notifications.email.enabled: true` и
`notifications.report.enabled: true`, заполненные `smtp_host`, `smtp_port`, `use_ssl`, `sender`,
`recipient` и `SMTP_PASSWORD` в `.env`. Если отправка выключена или не настроена, отчёт печатается
в консоль и сохраняется в `data/report/<дата>.json` — данные не теряются.

**«SMTP-сервер закрыл соединение».** Провайдер блокирует SMTP-вход: смените `smtp_host`/`sender` —
подробности в [notifications.md](notifications.md#если-smtp-блокирует-вход).
