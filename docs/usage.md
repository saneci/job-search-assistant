# Запуск и команды

`run.bat` (Windows) и `run.sh` (Git Bash / WSL / Linux / macOS) — обёртки: при первом запуске создают
`.venv`, ставят зависимости и Chromium, затем передают аргументы в `run.py`. После первой подготовки
можно запускать напрямую: `py run.py …` (Windows) или `.venv/bin/python run.py …`.

## Описание команд

```bash
run.bat --help      # список команд (Windows)
sh run.sh --help    # то же в Git Bash / WSL / Linux / macOS
```

| Флаг                       | Что делает                                                                 |
|----------------------------|----------------------------------------------------------------------------|
| *(без флага)*              | обычный цикл: поиск → оценка → отклики → отчёт                             |
| `--login`                  | открыть браузер, войти в hh.ru и сохранить сессию (`data/state.json`)      |
| `--config ПУТЬ`            | другая YAML-конфигурация (по умолчанию `config.yaml`)                      |
| `--install-browser`        | поставить Chromium для Playwright (не нужен при `browser.channel: chrome`) |
| `--notify-test`            | отправить тестовые письма по включённым видам и выйти                      |
| `--retry [СТАТУС]`, `--re` | повторить вакансии из дневных отчётов по прямой ссылке, без поиска         |
| `--excluded`               | синоним `--retry excluded`: только компании из `exclude_companies`         |

Примеры:

```bash
run.bat --login                     # обновить сессию
run.bat --notify-test               # проверить канал писем
run.bat --retry                     # повторить error + queued + excluded
run.bat --retry queued              # только отложенные: тесты, анкеты, капча
run.bat --retry error               # только упавшие
run.bat --excluded                  # только исключённые компании
sh run.sh --re --excluded           # то же самое: «excluded» перекрывает «all»
```

## Как работают команды `--retry` и `--excluded`

- вакансии берутся из всех дневных отчётов `data/report` со статусами `retry.statuses`
  (`error`, `queued`, `excluded` по умолчанию; `skipped` можно добавить в `config.yaml`)
- поиск и выдача не открываются: приложение идёт сразу по `url` из отчёта
- дедупликация не применяется; запись обновляется (`attempts + 1`) и переносится в файл сегодняшней даты
- лимиты `limit_per_run` и `max_vacancies` действуют как в обычном запуске
- `--retry` и `--excluded` - это не подкоманды, а обычные флаги одной команды запуска `--retry`, которая принимает
- необязательное значение статуса
- `--excluded` — самостоятельный флаг-синоним (отдельная команда для краткости), `./run.sh --re --excluded`
  сработает, но это избыточно: результат тот же, что у `./run.sh --excluded`.
- `--excluded` имеет смысл после того, как компанию убрали из `exclude_companies`: пока она в списке,
  вакансия снова получит статус `excluded`

Формат отчёта и статусы — в [logs-and-reports.md](logs-and-reports.md).

## Остановка выполнения программы

Ctrl+C — штатный сценарий: приложение сохраняет сессию, дописывает отчёт и печатает итог («Работа приложения завершена,
отправлено откликов: 2 из 20. …»). Трейсбека быть не должно.
